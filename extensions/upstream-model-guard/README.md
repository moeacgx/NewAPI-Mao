# 上游模型校验外置插件

上传 ZIP 安装的 Root 扩展，支持 Default 与 Classic。
勾选检测分组，为请求模型配置一个或多个允许的上游响应模型。
支持渠道白名单，可直接填写渠道 ID，也可搜索勾选，白名单渠道跳过本插件检测。其他渠道默认连续 2 个请求明确不匹配才关闭整条渠道，次数可设为 1 至 100。
ID 支持逗号、中文逗号、分号、空白或换行分隔，自动去重，最多 1000 个正整数；清空输入并保存可清空白名单。非法输入不能保存，未知 ID 在保存时由宿主拒绝并保留草稿。
同渠道跨模型、分组共用计数，正常匹配清零，未返回模型名跳过且不清零；流式多个片段只算一个请求。
在通知中心选择「上游模型不匹配，渠道已关闭」，绑定现有 Bot 和接收目标。

## 宿主要求

`0.2.1` 需要同时包含 `channel.upstream-model-guard` 和 `channel.upstream-model-guard-tolerance` 能力的 NewAPI-Mao 宿主支持。
清单的版本下限不能代替能力检查；原版或未含本项适配的旧宿主会拒绝未知能力，
不能只上传 ZIP 就获取实时响应拦截。

插件包负责双模板页面、语言资源和通知事件声明。
实时响应观察、配置校验、整渠道禁用事务及通知队列由配套宿主执行。
目前扩展运行时不加载外部 Go 代码，也不执行后台 JavaScript。

## 安装与操作

1. 升级到包含上述宿主支持的版本。
2. Root 打开「扩展模块 → 模块管理」，上传 `upstream-model-guard-0.2.1.zip`。
3. 显式启用插件，打开「上游模型校验」。
4. 在「渠道白名单 ID」填写需跳过的渠道 ID，或通过列表勾选；设置连续不匹配阈值。新增规则、勾选分组、填写请求模型与允许的上游模型（每行一个），按需开启检测并保存。
5. 打开「通知中心」，为模块事件选择已有 Bot、Chat ID 和消息模板并启用任务。

名称区分大小写，忽略首尾空白。同一分组与请求模型只能有一条启用规则。
关闭的是整条渠道，包含未参与检测的其他分组、模型和密钥。当前响应及在途请求不会撤回。
没有启用通知任务时仍会禁用渠道并记录原因。普通健康检查不会自动恢复；排查后在渠道管理手工开启。
异常记录显示当次连续次数/阈值及是否已关渠；未达阈值仅记录，达到后才发送通知。
修改配置会使旧计数失效，关渠后恢复从零计数。升级旧配置默认阈值为 2、白名单为空。
先升级全部宿主并迁移数据库，再上传此 ZIP；回滚旧宿主前先停用检测，避免忽略白名单与容错。

停用或卸载插件会停止新检测，但不会恢复已禁用渠道，也不删除主数据库中的规则和历史记录。
重新安装后需显式启用，原有已保存规则会保留。
多节点部署必须在每个转发节点安装并启用插件，配置与渠道状态使用共享主数据库。
启停、安装或卸载后须对各节点调用 Root 接口 `POST /api/extension-admin/refresh` 并核验状态；
共享模块目录不会自动刷新其他进程，单次请求负载均衡入口不能保证覆盖全部节点。
页面与通知展示分组名称；ID/code 仅用于内部匹配与提交，名称缺失时才回退原标识。

## 构建

在源码仓库运行：

```powershell
powershell -NoProfile -File extensions/upstream-model-guard/build-package.ps1
```

输出位于 `output/extensions/`，包含 ZIP 及 SHA-256 校验值。校验值用于文件完整性核对，不是发布者签名。
包内仅含 `manifest.json`、本文档与 `public` 运行资源，不包含 Bot Token、密钥、测试数据或宿主二进制。
