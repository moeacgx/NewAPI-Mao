# 请求体读取错误与 413 响应优化

## 目标

当请求体在读取或解析阶段失败时，向客户端和日志保留第一次读取的真实原因；当请求体超过 `MAX_REQUEST_BODY_MB` 时返回 HTTP 413，避免被误报成普通 400。

## 范围

- `GetRequestBody` 会在 Gin 上下文保存首次读取错误，后续重复读取返回相同错误。
- 普通分发入口、Midjourney 入口和官方任务插件入口根据错误类型选择 400 或 413。
- 原生任务插件路由在读取、UTF-8 校验和 JSON 解析失败时返回可诊断的错误详情。
- 请求体大小限制仍由 `MAX_REQUEST_BODY_MB` 控制，默认值及解压后限制保持不变。

## 兼容性与安全边界

HTTP 413 只表示请求体超过服务端限制，不改变鉴权、渠道选择、计费或重试契约。连接中途断开等读取错误仍返回 400，并使用首次读取的错误原因。任务插件路由继续隐藏插件执行异常，避免把供应商凭据或源码泄露给调用方。

## 验证

```powershell
go test -timeout 60s ./common ./middleware
git diff --check
```

回归覆盖请求体读取失败重复读取、超过大小限制的重复读取，以及普通分发和任务插件路径的状态码映射。
