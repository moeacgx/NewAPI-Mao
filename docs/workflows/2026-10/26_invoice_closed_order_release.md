# 发票关闭后释放来源订单

## 目标与范围

已支付发票关闭后仍占用来源订单，导致用户无法再次合并开票。本次修复后端共享订单契约，覆盖单笔充值、单笔订阅、合并申请及订阅充值镜像；Default 与 Classic 管理页同步限制关闭记录只能保持关闭。

## 方案与契约

- 关闭是终态：释放来源订单开票快照和合并关联的唯一占用，禁止重新改为待开票或已开票。
- 新增 `invoice_records.closed_orders_snapshot` 可空 TEXT 字段，关闭前保存合并订单明细；返回的 `orders` 继续保留历史明细，不改变现有响应结构。
- 来源订单列表及预览、提交入口按当前用户事务修复旧版已关闭记录，包括软删除的关闭记录。只清理来源状态仍为 `closed` 的快照，不能清除新申请的占用。
- 关闭的单笔记录不再阻止新申请；未关闭记录（包括软删除记录）继续防止重复开票。
- 重复保存关闭申请只更新管理员备注，不重新同步来源订单；历史关闭记录首次访问时补齐释放。
- 待支付取消继续保留迟到支付人工退款逻辑。支付历史、费用、账户余额不因关闭自动变化。

## 安全、兼容与回滚

继续使用来源订单行锁、条件更新及合并关联唯一索引防止并发重复申请；历史修复按发票 ID 顺序锁定。快照使用项目 JSON 包装函数。新增字段使用普通 TEXT，支持 SQLite、MySQL 和 PostgreSQL；无需人工批量修改线上订单。

升级由现有 AutoMigrate 增加字段。回滚旧版本会恢复旧的关闭占用语义，且旧版本不能读取已释放合并关联的快照，需先停止新的开票操作并评估业务状态；不应删除快照字段或重写支付历史。

## 验证计划

使用确定性数据库回归验证单笔及合并关闭后再次申请、订阅镜像、历史关闭与软删除记录、订单明细保留、重复关闭、新申请隔离、费用不变，以及未支付取消和迟到回调。

## 验证结果

- 修改前回归复现：关闭订单仍显示已申请，历史关闭订单预览返回“所选订单已经申请过发票”。

- Default：`tsgo -b` 类型检查通过；`vitest run src/features/invoices` 的 3 个文件、13 项测试通过。
- Classic：`node --test src/invoice-batch-request.test.mjs src/invoice-total-amount.test.mjs` 的 7 项测试通过。状态选择器仅保留关闭选项；顺带消除该文件未使用的 catch 变量和冗余三元分支，以通过文件级 lint。
- 两套模板修改文件执行 Oxlint，Default 执行 Oxfmt，Classic 执行 Prettier；开发文档执行 Oxfmt、检查新增相对链接与 `git diff --check`。
- 当前环境未提供 Bun 可执行文件，直接调用 Node 与对应工具二进制；依赖复用本机相同锁文件 SHA-256 的工作树，不变更依赖及锁文件。

## 共享契约与分享评估

用户订单响应结构不变，关闭后 `invoice_eligible=true`、`invoiced=false`，仍受支付成功、金额及近 30 天窗口限制。管理员不能将关闭申请重新开启，需新建申请；其他系统若操作发票状态，应按此终态约束处理。

- `NewAPIForDouDi`：建议分享关闭释放和幂等保护方案；是否采用需先确认其发票模块与来源关联结构，不能只移植列表筛选。
- `NewAPIModifyByGang`：建议分享相同修复思路；需同步适配明细快照迁移、历史占用和支付回调边界，不假定具备相同实现。
