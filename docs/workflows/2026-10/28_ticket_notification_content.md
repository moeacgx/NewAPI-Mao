# 工单通知显示用户正文

## 目标与范围

现有工单外部通知只包含标题、用户、分类和优先级，管理员无法直接看到用户的问题。本次为新建工单与用户追加回复的 `ticket_user_message` 事件加入当次用户正文，并同步 Default、Classic 通知中心的变量说明与示例。

## 方案与契约

- 在创建工单或保存用户回复的同一事务内，将当次正文快照写入事件的 `content` 字段；不查询最后一条消息，避免自动回复或后续回复混入历史通知。
- 默认模板末尾增加 `正文：{{content}}`。精确匹配的旧默认模板自动升级，已有自定义模板保持不变，可自行加入 `{{content}}`。
- 正文保留原始纯文本，由现有模板渲染器统一进行 HTML 转义。正文摘要的转义后预算为 2000 个 Unicode 字符，超出时保留完整字符边界并附截断说明；工单详情仍保留完整正文。
- 历史事件缺少 `content` 时，投递端仅为工单事件补充“历史通知未保存正文，请查看工单”；不回查、不改写历史事件，其他未知变量仍拒绝。
- 工单模板保存校验使用最长整数、转义后最大标题、2000 字符正文及最大提及名称样本，拒绝重复正文或附加文案导致超长的自定义模板；不改变其他事件的校验样本。

## 安全与兼容边界

- 继续只通知 Root 配置且启用的 Bot、任务及接收目标，不自动通知工单用户；管理员回复、自动回复和状态变更不新增通知。
- 通知配置和投递历史仍要求 Root 权限；现有系统不校验 Telegram 群成员身份，接收目标应由配置者确认。
- 不增加数据库列、生产 API 调用或真实消息测试，不改变工单权限、计费、路由及现有自定义模板。
- 新正文快照会进入通知事件与投递历史，适用现有访问权限和保留策略。上线后默认通知将携带用户提交内容。
- 主节点启动即自动迁移共享默认模板。旧投递器无法为缺正文的历史事件补提示，混合版本期间可能将其标记为永久失败。滚动更新应先升级 slave，在停止或隔离所有旧 master 投递 worker、等待在途派发结束后，再启动新 master 完成迁移并恢复投递；单 master 原地替换也必须确保旧进程先退出。回滚旧应用前应恢复不含 `content` 的默认及自定义模板。此次不执行发布或部署。

## 测试计划

- 模型：创建与多次回复的正文快照、自动回复隔离、摘要转义预算、旧模板迁移与幂等性。
- 控制器：事件变量和保存模板允许 `content`，未知变量与超长模板仍拒绝，权限契约不变。
- 服务：本地 HTTP 模拟验证实际发送正文、HTML 转义、长正文及历史负载兼容，不连接真实 Telegram。
- 前端：Default、Classic 分别验证变量说明、示例及国际化文案，执行相关测试和静态检查。
- 交付：同步长期文档、Markdown 格式与链接检查、`git diff --check`，记录实际验证结果及限制。

## 验证结果

- 红测确认原实现没有用户正文、旧模板不升级、历史缺字段不能使用正文模板；实现后对应回归通过。
- `go test -mod=readonly ./service ./controller ./model -timeout 60s -count=1`：2973 项通过；三包 `go vet` 通过。独立审查发现数字 ID 及提及名称样本偏短，补充边界红测并修正后，`./controller` 全量 834 项及 vet 再次通过。
- 本地 HTTP 模拟验证创建事件的正文、换行、HTML 转义、超长中文、emoji、转义膨胀及历史缺正文事件；默认模板在最长标题和提及名称下仍小于 4096 字符。未知变量继续拒绝，历史事件没有被回写。
- Markdown 使用仓库现有 `oxfmt` 格式化。5 份相关文档共核对 477 个本地链接，本次新增链接均有效；开发索引存在的 81 个旧失效链接与基线一致，未纳入本次修改。
- 不连接真实 Telegram，不读取用户 8257 的工单，不操作生产；未验证 MySQL/PostgreSQL 实库及真实浏览器外观。本次无新增表或字段，仍使用既有 GORM 任务迁移。

## 共享契约与分享评估

- 新增事件字段 `ticket_user_message.content` 及模板变量，既有任务、权限、路由与计费契约不变；自定义模板默认保持原样。没有向其他项目创建 Issue 或消息。
- `NewAPIForDouDi`：若同样使用工单外部通知，值得分享正文快照及摘要能力，能减少管理员回站查看的次数；需先核实其事件字段和权限契约。
- `NewAPIModifyByGang`：若沿用同版通知队列，可分享默认模板升级与历史负载兜底方案；需核对其模板迁移和 worker 生命周期，不能直接照搬部署步骤。
