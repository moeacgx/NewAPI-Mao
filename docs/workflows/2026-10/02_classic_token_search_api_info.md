# Classic 令牌搜索与 API 信息入口

## 目标与范围

修复 Classic 令牌列表中名称和密钥只能完整匹配的问题，并在“添加令牌”同一操作区提供已配置 API 信息的快速查看入口。本轮以 Classic 为页面改动范围；Default 令牌页已使用新版数据表布局，但当前没有 API 信息操作入口，因此不直接重写 Default 页面。

## 搜索契约

- `/api/token/search` 继续接收 `keyword`、`token`、分页参数，并支持可选 `status`；前端不拼接 SQL 通配符。
- 普通非空输入按字面量执行包含匹配，`%`、`_` 和 `!` 继续按字面量转义，避免用户输入改变查询语义。
- 显式通配符仍遵循现有校验和高令牌量保护；空输入不增加过滤条件。
- 查询仍使用 GORM `LIKE ... ESCAPE '!'`，兼容 SQLite、MySQL 和 PostgreSQL。

## API 信息入口

- 复用 `/api/status` 返回的 `api_info_enabled` 和 `api_info` 数据，不新增接口或持久化字段。
- Classic 顶部操作区增加轻量 Popover，展示路由、地址和说明，并支持复制地址。
- 没有配置或面板被禁用时显示明确空状态；不把后台 API 信息管理表格嵌入令牌页面。

## 验证计划

- Go：名称前缀/中间片段、密钥片段、特殊字符转义、分页和无结果搜索回归。
- Classic：API 信息入口、空状态、复制操作、桌面/移动布局，以及原有令牌标签选择测试。
- 执行受影响 Go 测试、Classic compat 测试、Prettier、ESLint 和 `git diff --check`。

## 验证结果

- `go test ./model ./controller -count=1 -timeout 60s` 通过。
- Classic 分组标签选择回归 21 项通过；API 信息入口的配置与空状态测试 2 项通过。
- 本次涉及的 Classic 文件通过 Prettier 与 ESLint 检查；Classic Vite 生产构建通过。
- `git diff --check` 通过。全量 Classic i18n lint 先前报告仓库范围内 460 处既有硬编码候选项；此次新增文案使用英文 i18n 键并补齐八个 locale 文件。
- Default 模板源码确认采用新的 API Keys 数据表与操作栏；本轮没有加入 API 信息按钮，也没有重排 Default 页面。

## 视觉与交互验证

Classic 令牌页在现有 Semi Table 上接入参考样式：API 地址与创建按钮、名称/密钥包含筛选、状态筛选、查看列选项、60px 行高与固定右侧操作栏。名称采用 600 字重，主体 14px/500 深色，时间为 12px/400 次级色；沿用主题变量兼容暗色。批量操作仅在选择后显示；复制密钥/连接信息、CC Switch、所有已配置聊天链接和删除继续使用真实处理函数。创建/编辑共用标签选择器，稳定 ID/code、额度单位和密钥按需读取契约保持。

本地验证覆盖桌面与 390px 窄屏、API 信息浮窗、名称和密钥包含搜索、启停、标签直接弹出选组、
自动分组冲突提示、移除冲突后多分组创建以及重复编辑回填。生产页面不使用演示数据，
本地截图仅作为视觉验收记录，不代表线上数据库或真实 API 调用。

状态参数 `status=0..4` 为可选字段；0/未提供不过滤，非有效整数拒绝。查询始终限定当前用户，在计数和分页前应用状态条件。Classic 防抖搜索，提交/启停后的刷新保留筛选。

正式组件追加验收：`model/controller/router` 测试通过；标签选择 21 项、API 信息 2 项、请求乱序回归 1 项通过。生产组件浏览器断言覆盖名称片段、服务端状态参数、启停、菜单、auto 冲突与创建、390px 无页面横溢及暗色。名称实测字重为 600、颜色为主题主文字色；生产构建和涉及文件 ESLint/Prettier 通过。

列表与搜索共用请求序号，旧请求不提交结果和加载状态；清空条件后旧搜索不得覆盖全量结果。每次翻页使用当前表单条件，避免依赖上一请求的搜索状态。
