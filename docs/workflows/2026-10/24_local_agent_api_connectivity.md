# 本地 Agent 接入与模型发现核验

## 问题与范围

用户反馈本地 Agent 无法调用，也无法获取模型列表，并授权使用提供的测试令牌对 zzapi
和 `deepseek-v4.1-flash` 发起真实请求。本项核验公网接口、实际调用记录及应用健康状态；
不修改用户 Agent 配置、站点配置、数据库或运行镜像。

测试令牌不写入本记录、仓库文件或诊断日志。诊断仅输出状态、耗时、协议结构及最短测试回复。

## 实际结果

- `GET /v1/models` 返回 HTTP 200、JSON 和两个模型，包含目标模型。
- `GET /models` 返回 HTTP 200、HTML 网页，不是模型列表。HTTP 200 不能单独证明模型发现成功。
- `POST /v1/chat/completions` 非流式返回 HTTP 200，具有回复、用量与 `finish_reason=stop`。
- 同一接口的流式请求以英文连通性指令和 256 Token 输出上限复测，返回 HTTP 200、
  `text/event-stream`、正文 `API_OK`、`finish_reason=stop` 和 `[DONE]`，没有 SSE 错误。
  该次首个正文约 7.9 秒，完整请求约 8.0 秒；只代表此次测试耗时。
- `POST /v1/responses` 非流式也返回 HTTP 200 和有效响应结构，但由于本次仅给 64 Token
  输出上限，响应状态为 `incomplete`。这项只证明接口连通，不证明完整 Agent 工作流兼容。
- CloudSSH 只读检查确认 zzapi 三个应用容器均健康，并在消费日志中找到本次四个生成请求。
  正常完成的流式请求记录输入 18、输出 15 Token；没有将上游响应头中的 UUID 当成本网关日志 ID。

## 接入边界与排查顺序

`router/relay-router.go` 中模型发现只经过 `TokenAuth → ListModels`，不会进入提示词装载、
渐进式发现或正式生成处理。因此本次没有证据支持“技能安装直接导致模型列表失败”。

客户端最终模型发现地址必须为 `/v1/models`。对于自行拼接 `/models` 的 OpenAI 兼容客户端，
Base URL 应包含 `/v1`；对于自行添加 `/v1` 的客户端，应按其规则填写站点根地址。
同时检查重复 `/v1/v1/models`，不能只根据设置项名称判断最终 URL。

若模型列表仍失败，应先取得 Agent 名称、脱敏错误和最终请求地址，再核对鉴权头、网络代理、
分组及模型限制。若生成失败，则另外核对使用 Chat Completions、Responses 或 Messages，
以及错误状态、工具调用和会话状态字段；单次 HTTP 200 不代表这些分支均已验证。

用户尚未提供具体 Agent 和原始报错，本项没有复现该客户端失败，也没有确认其根因。
本次测试不能证明全部本地 Agent、模型、流式组合、工具调用或持久会话兼容。

## 交付边界

本项仅记录排障证据，没有程序变更，无需重跑程序构建和单元测试。文档使用仓库现有
Prettier 格式化，并检查索引相对链接及 `git diff --check`。

没有新增跨项目协议，也没有可向 `NewAPIForDouDi` 或 `NewAPIModifyByGang` 同步的实现补丁；
两项目如出现同类接入问题，可以复用此处检查最终请求地址和响应类型的方法。
