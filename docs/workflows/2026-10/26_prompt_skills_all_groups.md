# 技能白名单“不限分组”

## 目标与范围

管理员可将已发布技能模板设为“不限分组”，令牌在任一启用的实际分组都可安装和装载，
无需维护分组白名单。Default 和 Classic 提示词中心均支持此选项、摘要显示和令牌安装状态。

## 数据与 API 契约

- `prompt_templates.all_groups` 是 AutoMigrate 新增的可空布尔列，不设置数据库默认值。
  存量行的 NULL 与 false 等价；只有 `all_groups = true` 开放所有当前启用的实际分组。
- 模板响应增加 `all_groups`。为 true 时 `group_ids` 与 `group_details` 为空数组，界面显示
  “不限分组”。管理员保存为 true 时服务端清空白名单关联，避免同时存在两种授权来源。
- 上架模板需设置 `all_groups=true` 或选择至少一个存在的白名单分组；下架草稿可不选分组。
  取消“不限分组”后须重新选择分组才能上架。
- 安装不限分组模板仍要求令牌至少有一个当前可用的启用分组。上架、安装启停、令牌状态、
  版本与模板项数限制保持原有要求。

## 授权边界

全文装载、渐进式技能目录和正文读取共用同一实时数据库条件：当前实际分组处于启用状态，
且模板要么明确白名单包含该组，要么 `all_groups=true`。白名单命中行为不变；分组停用、
模板下架、令牌失效或安装关闭都会阻止读取。`auto` 在路由选定实际组后再做判断，不扩大
令牌分组或渠道路由权限。

## 兼容与回滚

旧节点不识别新增列，会按白名单处理，因此不会装载“不限分组”模板（失败关闭，不越权）。
旧节点保存模板时沿用显式字段更新，不会覆盖新列。回滚到旧版本后，不限分组模板不会被装载；
新增列无需删除，重新指定白名单即可恢复旧版本行为。

## 验证

- 模型回归覆盖：上架校验、保存清空白名单、任一启用组安装/目录/正文/全文装载、停用组拒绝、
  无可用分组的令牌拒绝、白名单兼容、NULL 存量处理及取消不限分组后即时撤权。
- SQLite、MySQL、PostgreSQL 矩阵回归覆盖同一组授权语义。
- Default 与 Classic 回归覆盖编辑器切换、摘要显示、令牌卡片和分组名称展示。
- 本地组合验证：`go test ./service ./controller ./model ./router -count=1 -timeout=60s` 通过；
  Default/Classic 定向组件测试、Default 类型检查、格式检查与双模板生产构建通过。
  这些是本地验证，不代表 GitHub CI、发布或生产部署已完成。
