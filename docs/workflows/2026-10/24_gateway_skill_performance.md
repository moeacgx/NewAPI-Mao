# 云端 Skills 资源控制与性能优化

## 目标与范围

降低渐进式技能请求对网关的 CPU、临时内存和数据库的影响，并限制突发请求占用。
仅修改后端共有链路，Classic 与 Default 沿用现有 API 和页面，无前端改动。
从 `c48d7cea7` 开始，在独立工作树开发；不调用真实模型、不访问线上数据库、不部署。

## 已核实问题

- 每轮发现会重新解析、复制并编码完整历史，长 Agent 上下文放大分配和垃圾回收。
- 每页读取及正式生成前均重新读取文件，主文件读取还会读取全部资源路径。
- 读取使用公共模板排他行锁，多用户读取同包时可能在 MySQL/PostgreSQL 排队。
- 已有八轮发现、单轮八工具、192 KiB 正文预算和响应大小限制，缺少技能专用准入和时限。

## 实施方案

1. 增加每实例独立技能请求并发和在途原始正文大小预算，无无限排队；超额在模型调用前明确失败。
   准入槽位覆盖完整客户端请求并在结束、失败或取消时释放，跨组重试复用同一请求槽位。
   单独约束私有发现阶段时长，正式回答继承客户端原有上下文，不被私有阶段期限截断。
2. 复用请求内不可变 JSON 历史和字段，只追加技能工具结果，保留未知字段、显式零值、
   多模态内容及四种协议的工具往返契约；不裁剪用户历史，不降低现有文件和分页读取能力。
3. 对版本化技能正文和文件目录使用有界缓存；权限与发布状态继续实时检查，不能缓存授权。
   在保证修改、撤销和并发读取一致性的前提下，减少重复查库和公共模板锁占用。
4. 对技能发现设置独立输出预算，避免继承客户端极大的正式回答输出额度而放大私有缓冲。

配置默认值、错误码、缓存一致性及可验证的优化结果随实现更新到本记录和长期专题文档。
缓存边界采用模板稳定 ID 和版本，不使用名称、分组显示名称或令牌明文作为缓存身份。

## 安全与兼容边界

- 保留每轮真实用量预扣、结算和消费日志，已发生的模型调用正常计费。
- 保留正式生成前对令牌、绑定、分组、模板版本和发布状态的检查。
- 保留未知工具拒绝、客户端工具交回 Agent、回复技能使用标识等行为。
- 数据库实现同时兼容 SQLite、MySQL 5.7.8+ 与 PostgreSQL 9.6+。
- 不增加跨请求永久激活状态，不缓存用户历史或模型回答。
- 准入限制为单实例保护，整个部署容量为各实例额度之和，不声称是共享集群限额。

## 验证计划

- 确定性回归：准入拒绝、取消释放、重复释放、跨重试、超时退款与正式阶段上下文。
- 四协议普通/流式与未知字段、显式零值、工具往返和技能正文注入回归。
- 缓存命中后覆盖修改版本、下架、卸载、停用令牌和分组限制；检查缓存容量与并发访问。
- 模型、服务、控制器相关测试均使用 `-timeout=60s`，独立 `relaykit` 构建和根模块构建。
- 使用前轮相同本地模拟上游、100 用户、8 KiB 正文、两轮发现，
  比较 16 KiB、128 KiB、1 MiB 历史；性能对照调高准入额度以保持相同并发，
  另用确定性测试验证默认保护，不将限流造成的请求减少算成性能提升。
- 文档格式、相对链接、`git diff --check` 和独立代码审查。

## 验证结果

### 配置与行为

- 每实例默认 16 个在途技能请求、原始正文合计 32 MiB；分别由
  `GATEWAY_SKILLS_MAX_CONCURRENT`、`GATEWAY_SKILLS_MAX_INFLIGHT_CONTEXT_BYTES` 配置。
  单请求超预算返回 413；并发或合计字节预算不足返回 429，不排队。
- 每次路由尝试的整个私有发现阶段默认 120 秒，不逐轮重置；正式回答恢复客户端上下文。
  其他可重试故障切换路由后，新的发现尝试重新计时，但并发及正文额度仍共用。
  私有期限到达返回本地 504，父请求已取消时保留父取消语义，不误记渠道故障。
- 私有模型每轮输出默认最多 4096 Token，保留较低客户端上限；正式回答仍使用原请求预算。
  手动思考保留模式并收紧预算，不兼容的过小上限明确返回 400。
- 正文页及目录共用固定 32 MiB 估算容量的版本化 LRU；缓存不保存授权、聊天历史或回答。
  热缓存仍在事务内实时复核权限及版本，正式生成前再次复核；更新版本、下架和卸载继续生效。
- 环境变量、协议别名、错误码、清缓存与数据库锁语义见
  [长期专题](../../developer/token-prompt-center.md#云端-skills-资源保护与内容缓存)和 `.env.example`。
  原始正文预算及缓存计账均不等于进程内存硬上限，期限也不能强制中断不配合 Context 的数据库等待。

### 自动化验证（2026-10-25）

- `GOARCH=amd64 go test ./model ./controller ./service ./router ./pkg/perf_metrics -count=1 -timeout=60s`
  全部通过：model 37.541s、controller 11.974s、service 34.678s、router 21.776s、perf_metrics 2.141s。
- 确定性用例覆盖 429/413 前置拒绝及退款、普通请求不占技能额度、正式流式回答期间持续占用、
  流结束与取消后的释放、首轮超时退款、已有成功轮次后的超时保留消费，以及父取消与子期限的竞态。
  父取消路径同时验证直接发现与完整 Relay，不重试、不封禁、不写渠道错误或未发生的消费日志。
- 四协议测试覆盖多轮历史复用、出站快照独立、失败续轮原子性、未知字段、精确数字、显式零值、
  多模态与推理签名，以及输出预算和别名优先级。既有普通/流式技能和客户端工具交回回归通过。
- 内容缓存验证版本隔离、容量淘汰、目录副本、UTF-8 分页、跨令牌实时授权和失败事务不发布缓存。
  共享锁验证三数据库 SQL 方言，未连接真实 MySQL / PostgreSQL，不能宣称实库争用收益已验证。
- 环境为 Go 1.25.5、Windows、目标 GOARCH=amd64；本机无 gcc，未运行 `-race`。
  本轮仅改后端共有路径，Classic / Default 没有前端变更；根构建复用同基线已构建的双模板静态产物。
- 根模块 `go build` 和 `relaykit` 内 `GOWORK=off go build ./...` 均通过。
  根模块首次被本机 32 位链接器的映射内存限制阻断，改用已有便携 Go 1.25.5 windows/amd64 后成功，
  未更改系统安装或项目依赖。
- Go 格式、四份修改文档的仓库格式检查及 `git diff --check` 通过。
  相对链接检查覆盖 409 个去重链接，本次新增的四个链接及对应锚点通过；
  开发索引原有 81 处指向缺失历史文档的链接，已核实来自基线，本次未扩大范围修复。

### 100 并发前后对照

使用同一份隔离诊断、同一台 Windows / i5-14600K、GOMAXPROCS=4，旧版 `c48d7cea7`
与优化工作树串行运行。100 个独立账号及令牌读取同一个双技能包中的 8 KiB 主文件，
每个技能请求两轮私有发现加一轮正式生成；普通对照只有正式生成。
SQLite 内存库、完整鉴权/装载/Relay/按次预扣结算/消费日志，启用本地 Token 估算，模拟上游位于独立进程。
各阶段用屏障固定 100 个在途请求，预热后再采样；每个场景独立进程，重复两次并反转版本执行顺序。
共 24 个场景，全部各 100 请求成功；普通日志 101 条、技能日志 303 条，均含预热。

容量对照仅在测试进程将并发调为 128、正文总预算调为 256 MiB，以保证两版完成相同工作量；
限流未作为性能改善。诊断源码、原始输出和汇总留在忽略目录 `.local-tests/skill-capacity/`，不提交临时入口。

下表均为“技能请求减普通请求”的增量；分配量是整轮累计分配，不是同时存活内存：

| 单请求历史 | 优化前额外 CPU（毫秒/请求） | 优化后额外 CPU（毫秒/请求） | 额外累计分配减少 |
| ---------- | --------------------------- | --------------------------- | ---------------- |
| 16 KiB     | 6.25–9.84                   | 9.53                        | 7.7%–7.9%        |
| 128 KiB    | 24.53–28.28                 | 22.97–24.53                 | 10.5%–10.7%      |
| 1 MiB      | 163.59–187.50               | 128.44–146.09               | 11.6%–11.9%      |

1 MiB 历史的技能额外 CPU 在两轮分别减少 22.1% / 21.5%；100 个技能请求累计分配由
14160.80–14163.48 MiB 降至 13244.34–13253.29 MiB，减少约 6.4%–6.5%。
技能相对普通请求的额外累计分配由 7796.32–7814.17 MiB 降至 6886.06–6890.79 MiB。

峰值驻留内存没有稳定显著下降：100 个 1 MiB 技能请求总峰值优化前 1814.89–1872.16 MiB、
优化后 1858.13–1889.91 MiB；减去空闲及普通请求后的额外峰值前 654.73–685.55 MiB、
后 667.84–696.18 MiB。额外存活堆前 316.93–318.96 MiB、后 314.50–315.55 MiB，变化很小。
因此并发和正文预算是防止突发内存占用的主要新增保护，不能将累计分配减少宣传成等比例降低常驻内存。
16 KiB 的 CPU 没有稳定收益，其中一次更高；小请求不承诺加速。

进程 CPU 为 GetProcessTimes 用户态与内核态之和；内存为各阶段 GC 后存活堆和进程峰值工作集。
本次仅 Chat 非流式、非透传、小目录、单页与短输出，不含真实推理延时、TLS、Redis、
MySQL/PostgreSQL、更多发现轮次或更大目录，也不能据此声称生产吞吐上限或通用百分比。
缓存和 JSON 复用不减少私有模型轮数、输入 Token 或上游费用。

另有标准微基准：八轮、1 MiB 历史，四协议状态 API 约 10.61–10.63 MB/op，
当前无状态兼容 API 约 19.11–19.15 MB/op，分配减少约 44.5%。
它比较本分支两种调用方式，不是旧版完整链路对照，也不是生产吞吐；不可与上表混称。

### 交付边界

本地实现与验证完成后提交在 `feat/gateway-skill-performance-20261024`；本轮未推送、未发布、未部署，
未访问线上数据库或真实供应商。准入保护只对实际命中渐进式技能的请求生效，默认最多 16 个同时在途，
不是站点只能供 16 位用户使用；超额客户端需处理 429。多实例容量为各实例额度之和。

共享契约影响为三种新的本地资源错误及私有输出预算，认证密钥、模型 ID、正式响应协议和实际用量计费保持原契约。
NewAPIForDouDi 可评估历史复用、有界内容缓存和准入保护，但需适配其技能授权与计费链路；
NewAPIModifyByGang 若已有渐进式网关工具循环同样值得参考，若只有全文提示词装载则不应整套移植。
本轮没有向兄弟项目创建通知、Issue 或 PR。
