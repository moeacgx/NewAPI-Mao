# 双主题管理员查询用户时联动当前连接

## 目标与范围

Classic 与 Default 使用日志按用户 ID 或用户名提交查询后，顶部连接面板和分页抽屉读取同一用户的实时连接。
查询输入未提交时不切换对象；清空用户并提交后恢复本人连接。Default 本次新增通用日志连接入口和互斥的
用户 ID/用户名查询；“仅本人”视图始终查询本人。令牌页活动筛选保持 Classic 既有范围。

## 方案与接口

- 新增管理员只读接口 `GET /api/log/active`，必须且只能提供 `user_id` 或 `username`，用户名精确匹配。
  其他分页、搜索、状态及令牌参数沿用本人接口；返回额外 `subject: {id, username}`。
- 管理员接口由 `AdminAuth` 保护；本人接口仍只读会话身份，不接受跨用户身份覆盖。
  非法参数返回 400，用户不存在返回 404，存储不可用返回 503；响应禁止缓存。
- 使用日志仅保存已提交的用户条件，面板显示查询对象；抽屉继承对象。切换用户取消旧轮询、
  丢弃旧快照并重置抽屉，避免上一用户连接出现在新对象标题下。
- 指定用户没有连接时显示空状态；加载和错误状态不能冒充零连接。当前连接按实时生命周期查询，
  不受历史日志时间范围影响；保留现有结束后 5 秒显示和活动统计规则。
- 两套主题的连接观察 GET 设置 10 秒超时，超时后显示局部错误并继续轮询；该超时不作用于转发请求。
  Default 切换查询用户或本人/全部范围时隔离旧日志和旧统计，同一主体翻页仍可保留已有数据。

## 安全与兼容边界

不新增全站连接扫描，不返回密钥、提示词或上游信息；无数据库迁移、计费、路由或生产配置更改。
用户名解析使用参数化模型查询，查询条件由后端校验，普通用户不能通过前端参数越权。

## 双主题实现（2026-10-22）

- Default 复用相同的本人/管理员只读接口，保持 3 条预览、10 条分页、实时轮询、隐藏页面暂停及结束耗时冻结。
- 用户 ID 与用户名条件互斥，日志、统计和连接均使用已提交条件；输入草稿不改变当前观察对象。
- 切换对象、仅本人视图或路由时取消旧请求并隔离快照；加载、错误、无连接分开展示。
- Default 使用自身 Card、Sheet 和主题变量，独立验证；线上不随本地修改自动更新。

## 线上只读诊断（2026-10-22）

- 线上三个应用节点实际运行 `.351`，提交为 `2088c02169b3ed1dbd8b7c58dc1811ef777c90b6`，
  均健康、重启次数为零；三个状态接口均返回 200，Redis 配置相同且连接正常。
- 三次采样分别存在 123、124、120 条有效连接租约，涉及 52～54 个用户，说明全局连接跟踪仍在运行。
  这些聚合数据不能证明反馈用户本人的请求正常。
- 生产版本仍固定查询 `/api/log/self/active`，管理员按其他用户筛选日志时，连接面板继续读取管理员本人；
  本人连接数为零且没有接口错误时，面板直接隐藏。本工作项修复该筛选缺陷，但尚未部署。
- 反代的 `api.maolaoapi.cc` 仅开放 `/v1` 路径，匿名 `/v1/models` 返回预期 401；
  `/api/*` 返回 404 符合既有路由规则。不能据此判断网页登录入口的连接轮询失败。
- 尚未核对网页登录账号与客户端令牌归属，也未取得用户浏览器连接接口的实际响应；
  不能将管理员筛选缺陷认定为用户全部故障的唯一根因。
- 所有检查均为只读，未修改生产配置、容器或数据，也未调用收费上游。
