# .357 Classic 提示词界面与充值客户端 IP 发布

## 发布范围

在 `.356` 基础上纳入用户授权的 #358 和 #357；#359 上游模型守卫来源清理仍开放，不纳入本次版本。早期重复 PR 的关闭只是整理，不增加发布代码。

- #358：新订单型充值日志使用下单时保存的 `TopUp.RequestIP`，与消费日志共用 Gin 客户端 IP 解析链，遵守用户与全局记录开关。支付回调与管理员补单地址不覆盖订单地址；历史充值日志继续脱敏。
- #357：仅优化 Classic 已安装提示词弹窗、分类筛选与技能类型控件。令牌徽标与提示词中心共用弹窗，图标区分技能与合集，支持草稿放弃与键盘筛选。保存和卸载请求、权限及计费契约不变。Default 不包含本次界面改动。

## 发布步骤与门禁

1. #358 已合并为 `cb85226bdd526d291d1a7c447663d78f8c7ec30c`。#357 同步该基线，逐行保留文档索引双方条目，重新验证并等待新提交 CI。
2. #357 合并后，从最新 `custom-main` 提交独立版本 PR，将 `VERSION` 更新为 `v1.0.0-rc.10.1.10.357`，通过 CI 后串行合并。
3. 仅在准确版本提交打附注标签，等待 Linux 与 Docker 双架构发布工作流完成。
4. 核对 Linux 资产和 SHA-256、镜像 amd64/arm64 清单与 version/revision，再确认 GitHub Release 为最新正式发布。
5. 本次只发布源码、二进制及容器镜像，不更新 zzapi 或 maolaoapi 的运行容器。

## 数据与回滚

- 相比 `.356` 无新增数据库结构或迁移，不修改支付金额、结算幂等、可信代理配置或历史数据。
- 新日志保留服务端订单来源标识，普通用户日志继续剥离管理员信息；没有订单地址或不允许记录时，IP 保持为空。
- 回滚到 `.356` 会重新隐藏新增充值日志 IP，并恢复 Classic 旧界面；订单和金额不受本轮修改影响。
- 线上 IP 准确性仍取决于部署环境的可信反代链；本地请求集成不等于生产验收。
