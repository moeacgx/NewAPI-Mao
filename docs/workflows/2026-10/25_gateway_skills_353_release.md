# .353 云端 Skills、令牌限制与工单中心整合发布

## 目标与范围

将渐进式云端 Skills、正文读取与 Agent 工具交回、回复标识及资源优化完整合入
`custom-main`，同时整合 PR #323 的令牌分组渠道限制、#324 的双主题连接快照状态、
#325 的双模板工单中心。用户于 2026-10-25 明确授权上述合并与发版。

本项只发布源码、Linux 二进制与多架构镜像，不更新运行中的 maolaoapi 或 zzapi 容器。
旧 PR 先逐项确认是否已等效落地、被后续方案替代或仍有独立差异，不因可合并就重复整合。

## 方案与兼容边界

- 以主分支为最终集成基线，保留双方业务和翻译；通过 PR 留存合并与验证记录。
- Skills 读取使用模型工具调用，实际读到的正文进入该次正式生成上下文；不安装本地文件，
  不代替 Agent 执行脚本。一次客户端请求可产生多轮上游用量和消费日志。
- 每实例默认最多 16 个在途 Skills 请求、32 MiB 原始正文预算；私有发现最多 120 秒、
  单轮输出最多 4096 Token。预算不等于进程内存硬上限，不能把本地对照当成生产容量保证。
- 正文页及目录缓存以版本区分，授权实时查库；下架、卸载、停用与实际分组限制仍然生效。
- 令牌渠道限制持久化使用稳定分组 ID，展示当前名称。新增 `token_groups.channel_id`；
  先升级全部节点再配置限制，混用旧版无法保证限制。回滚前须清理新限制。
- 渐进式存储及工单新增普通表和字段，使用 GORM 兼容三种数据库。
  已有渐进式业务数据后不能直接回退不理解该模型的 `.352`；部署前备份，优先向前修复。
- 工单普通用户只访问本人会话；管理端校验管理员与工单权限。批量更新使用版本及事务，
  软删除保留审计。自动归档默认关闭，由主节点任务执行，通知外发不包含工单正文。
- 连接快照改动只调整刷新和过期状态展示，不改变统计及计费，也不代表集群连接完整性保证。

## 验证与发布门禁

- 先审查 #323、#324、#325 与旧 PR 的实际差异，再运行最终组合验证。
- 后端执行相关及全量回归，单包超时 60 秒；单独验证 `GOWORK=off` 的 relaykit 构建。
- Default 执行类型、相关交互测试与生产构建；Classic 执行相关交互测试与生产构建。
- 文档格式、相对链接与 `git diff --check` 检查；不得提交凭据、日志、截图和构建产物。
- 合并前和合并后 CI 均通过后，才在最终主分支提交创建 `.353` 标签。
- 串行发布，避免 Docker `latest-*` 被其他标签构建交错覆盖；验证 Linux 资产校验和、
  固定镜像架构、源码 revision 与 `latest` 摘要，再将 Release 设为 Latest。

## 跨项目边界

对接方密钥和模型 ID 不变；渐进式读取增加内部上游轮次及实际计费，资源不足可能返回本地
413、429、504。令牌渠道限制会收紧选渠；工单是新增管理业务，不改既有 relay 请求结构。

NewAPIForDouDi 可评估缓存、准入保护及按分组限定渠道，但需要适配自己的授权、选渠与计费。
NewAPIModifyByGang 可评估技能资源保护和工单流程，需核对双模板、通知和管理员权限。
