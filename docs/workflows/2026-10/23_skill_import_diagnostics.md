# 技能导入正文错误定位

## 问题与范围

仓库根目录包含 skills/ 时，现有导入器会递归查找 SKILL.md；目录布局本身无需调整。
原错误将空正文、无效 UTF-8 和超过 32768 字节合为一条消息，且没有文件路径，
管理员无法确定导入失败的具体原因。本项只修正后端诊断，Classic 与 Default
沿用原有错误展示，不修改页面、导入接口、大小限制或装载行为。

## 方案与契约

- 单项正文区分 UTF-8 无效、空正文、正文超限；超限显示实际 UTF-8 字节数与上限。
- 合集内的错误指出技能标题，拼接总量超限独立提示，包含标题与分隔符开销。
- ZIP 和公开仓库导入在解析错误外补充文件相对路径，不返回正文、认证材料或完整仓库地址。
- 仍然只返回完整的有效草稿；失败不保存、不截断、不跳过问题文件。
- 不需要数据库迁移。既有的 32768 字节单项限制和 65536 字节令牌总量限制保持原样。

## 验证计划

使用确定性用例验证中文 UTF-8 字节边界、空正文、单项及合集超限，
并通过 ZIP 和模拟 GitHub HTTP 返回验证错误包含文件路径且失败不返回草稿。
执行 Go 定向测试（每包超时 60 秒）、相关包测试、文档格式及链接与差异检查。

## 验证结果

- 定向回归先在旧实现失败，再在修复后通过：模型正文诊断，以及 ZIP、仓库文件定位。
- `go test ./model ./service ./controller -count=1 -timeout=60s` 通过，
  三包分别耗时 34.082 秒、30.372 秒、4.948 秒。
- 示例错误：`技能文件 "skills/b/SKILL.md"：提示词正文为 32769 字节，超过 32768 字节上限`。
- 独立只读审查未发现阻断问题。文档已使用仓库现有 Prettier 格式化，
  本项新增相对链接及 `git diff --check` 通过。
- 只调整后端错误消息，两套前端继续显示接口返回的错误；本项未修改或构建前端，
  未取得用户私有技能原件，不能据此认定截图中是哪一个文件或哪一种正文错误。
- 本地修复尚未发布或部署。没有生产数据、表结构或原有 API 请求字段变更。

## 跨项目影响

错误响应仍沿用原 `success/message` 契约，仅细化管理员可见消息。
NewAPIForDouDi 与 NewAPIModifyByGang 均未核实有同一导入器，当前不建议直接移植；
若后续接入该功能，建议同时采用文件定位与字节数诊断，不需要改变模型调用接口。
