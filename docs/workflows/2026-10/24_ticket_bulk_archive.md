# 工单批量操作与超时归档

## 目标与范围

继续扩展当前未提交工单功能，暂停 PR 操作。Default 与 Classic 均支持管理员勾选当前页工单、批量改状态、批量软删除以及配置超时自动归档。保留已完成的创建后单次自动回复。

## 契约与安全边界

- 新增 `archived` 状态，与 `closed` 分开；两者均须先重新打开才可回复。个人用户仍只能设置 `open/closed`，可以重新打开自己的归档工单。
- `PUT /api/ticket-admin/batch/status`：`{tickets:[{id,version}],status}`；返回 `data:{updated_count}`。
- `POST /api/ticket-admin/batch/delete`：`{tickets:[{id,version}]}`；返回 `data:{deleted_count}`。仅软删除，隐藏于双方列表/详情/回复/状态接口，保留会话和操作审计。没有物理清理或回收站恢复入口。
- 每批 1–100 个不同正整数 ID，版本必须为正整数；非法/重复输入返回 400，任一不存在返回 404，任一版本过期返回 409；整批事务提交或回滚，不产生半批成功。前端二次确认，筛选/翻页/账号切换后清空选择，失败保留选择并提供刷新提示。
- 以上写入要求管理员及 `tickets:write`；普通用户和只读管理员不得执行。
- `GET/PUT /api/ticket-admin/automation/auto-archive`：`{enabled,inactive_days,statuses}`；读取要求 `tickets:read`，保存要求 `tickets:write`。默认关闭、30 天、`statuses:["resolved","closed"]`；天数整数 1–3650，状态是 `open/processing/resolved/closed` 非空去重子集。管理员可显式选择待处理/处理中工单。
- 未活动按 `updated_at`（最近创建、回复或状态变化）计算。主节点每分钟检查至多 100 条，逐笔锁定并重核状态/截止时间，版本条件保护并发回复；归档后不会再次命中。配置启用后也适用于已有工单。
- 批量变更、删除与自动归档写入事务内操作审计。状态变更/归档复用 `ticket_status_changed` 通知与现有事务去重；软删除仅审计，不新增外部通知。自动归档操作人 ID 为 0、角色为 system。
- 新增软删除字段和审计表，兼容 SQLite、MySQL、PostgreSQL；不修改现有正式数据，不执行生产操作。

## 实施与验证

后端由主代理单写；两个前端代理各自负责独立模板、测试与语言文件，文件范围互不重叠。先编写回归并观察缺失能力失败，再实现。检查权限、批量事务、版本冲突、软删除访问隔离、归档边界/重复执行/回复延期/通知回滚。前端检查选择与确认、只读权限、失败草稿、账号切换、归档状态与配置校验，并运行类型/lint/构建及真实本地预览。单元测试进程设置 60 秒上限。

## 实施结果

- `Ticket` 增加 GORM 软删除字段，新增 `TicketActionLog` 并在普通/快速迁移均登记；删除不物理移除消息。批量操作按 ID 排序锁定并先验证整个集合，任一通知/审计失败全部回滚。
- 自动归档复用系统任务注册，类型 `ticket_auto_archive`，任务结果为 `archived_count`，失败只记录固定错误，仍保留之前已成功归档的计数；30 秒子上下文服从任务租约取消。
- 保留初次自动回复，移除保存配置时重复调用 `InitDBColumns` 的全局写入，改由测试 fixture 正确初始化方言，生产仍复用原 `UpdateOption` 的事务保存。
- 两模板增加当前页选择、版本快照、两种确认弹窗、归档状态与规则配置；顺带修复原自动回复草稿刷新及跨账号回调问题。通知字段说明同步包含 system 角色。

## 跨项目与分享评估

新增可选管理员 API、archived 状态及通知 actor_role=system；使用工单接口的客户端需要识别归档，模型、计费与 API Key 契约不变。

- NewAPIForDouDi：适合分享批量客服处理和乐观版本/整批事务保护，需核对其管理员授权及数据结构后移植。
