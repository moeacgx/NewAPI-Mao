# 技能合集与分类

## 目标与范围

沿用双模板提示词中心已定稿界面，增加单技能和技能合集，以及管理员维护的平级技能分类。
本轮先实现和本地验证，不沿用上一轮发布脚本直接部署含新数据字段的版本。
按追加需求，提供 ZIP 导入、仓库链接导入和仓库内置技能商店，管理员导入草稿后编辑并保存到站点。

## 数据与接口契约

- 模板新增 `kind`（`prompt` 或 `bundle`）、`category_id`、`category_name`、`skills`、`skill_count`。
  旧模板及省略 `kind` 的请求按 `prompt` 处理，未分类为 `category_id=0`。
- `prompt` 使用既有 `content`，技能数为 1；`bundle` 的 `skills` 为 2 至 16 项
  `{title,content}`，按数组顺序装载，标题 1 至 80 字符且包内不重复。
  管理端可编辑各项，用户摘要仅有 `{title}`，不返回任何正文。
- 合集内部技能作为该合集的组成内容，不引用其他模板、不嵌套合集；使用合集自己的白名单、
  上下架和版本。安装、排序、启停及卸载为一个整体，占现有 8 项上限中的一项。
  令牌技能徽标继续统计安装项数，合集卡片和详情另展示内部技能数及标题。
- 合集正文为 `## 技能：标题\n正文` 按顺序以空行拼接，由服务端生成；客户端 `content` 不参与合集运行时。
  单项正文及最终拼接正文仍遵守 32768 UTF-8 字节，令牌启用正文合计仍为 65536 字节。
  保存、重新上架、安装和运行时沿用既有额度与长度保护。
- `prompt_categories` 保存稳定 ID、名称和版本；模板关联稳定分类 ID。
  `GET /api/prompt-center/categories/` 为登录用户返回分类摘要；
  `POST /api/prompt-center/admin/categories/` 创建，
  `PUT /api/prompt-center/admin/categories/:id` 改名并校验版本，管理员专属。
  分类名称 1 至 40 字符、不重复；不提供删除，避免既有安装和筛选出现悬空分类。
- 分类不授予权限，不改变分组白名单、令牌限制、计费或真实 Skills 执行边界。
  仍仅装载文本，不运行脚本、附件或工具。
- 使用 GORM 与 TEXT 存储，兼容三数据库；迁移只新增字段和分类表，历史正文与安装关系保持。
  合集内部明细用 `skills_json` TEXT 保存，通过 common JSON 包编解码；不直接暴露存储字段。

## 页面与验证计划

双模板保留当前浅蓝卡片风格。目录提供全部/未分类/分类筛选及单技能/合集类型筛选；
卡片显示类型、分类、技能数，合集可展开标题列表。管理员编辑器选择类型和分类，
新增/移除/排序内部技能；管理弹窗新增与改名分类。安装弹窗显示合集信息，不显示正文。

后端覆盖旧数据兼容、合集校验和装载顺序、版本冲突、分类改名、摘要无正文、实际分组与长度上限。
前端覆盖筛选、合集编辑、分类管理、安装详情及失败保留草稿；运行受影响测试、检查和双模板构建。
浏览器检查本地桌面及手机布局。验证结果随实现补充。

## 压缩包与商店

- `POST /api/prompt-center/admin/import/archive` 接收 multipart `file`，仅管理员。
  ZIP 压缩内容最多 2 MiB、最多 128 个条目、声明与实际解压累计最多 512 KiB。
  仅读取各目录的 `SKILL.md`；没有 SKILL.md 时读取 Markdown 文件。按路径排序。
  支持 YAML front matter 的 name/description；剥离 front matter 后作为技能正文。
  单项导入为单技能，多项为合集；超出 16 项、非法路径、符号链接、损坏 ZIP、
  非 UTF-8 或超出既有正文限制均拒绝，不写入服务器文件系统、不执行脚本。
  脚本与附件不进入站点模板或后续调用，页面明确文本装载范围。
- 仓库 `skill-store/` 保存版本化 `index.json` 和各技能 Markdown；编译时嵌入，离线亦可浏览内置快照。
  `GET /api/prompt-center/admin/store/` 返回摘要数组，`?source=online` 显式刷新官方仓库目录；
  刷新失败返回错误并保留前端原列表，不伪称在线成功。
  商店在线源固定为本项目 `custom-main` 分支的 `skill-store/`，不接受自定义商店 URL，不跟随重定向。
  网络请求有超时和大小上限，导入时逐文件校验目录中的 SHA256。
- `POST /api/prompt-center/admin/store/:id/import` 根据不透明商店 ID 读取内置或在线来源，返回模板草稿。
  列表包含 `id/title/description/kind/category/skill_count/source/version`，只管理员能访问商店正文。
- `POST /api/prompt-center/admin/import/repository` 接收 `{url:"https://github.com/owner/repo"}`，仅管理员。
  支持公开 GitHub 仓库、目录或单个 SKILL.md 链接；通过 GitHub 官方 API 获取目录及固定提交，
  只从官方原始文件域名读取同一提交内的 SKILL.md，不克隆仓库、不执行任何内容、不发送站点凭据。
  仅允许 HTTPS 官方主机，不跟随重定向，不接受任意下载 URL、私有仓库或自定义 Git 服务。
  单次请求总时限 30 秒，目录响应和文件读取均有大小上限，最多导入 16 个技能，
  最终正文仍遵守 32768 字节；限制不满足时整体拒绝，不静默截断合集。
  目录语义参考 [GitHub Git Trees API](https://docs.github.com/en/rest/git/trees#get-a-tree)，
  远端返回 `truncated=true` 时拒绝导入，避免把不完整目录误当作完整合集。
  根链接使用仓库默认分支；目录和文件链接支持分支、标签或完整 40 位 commit SHA。
  分支及标签按最长完整前缀匹配，支持含 `/` 的引用；同名分支与标签歧义时要求改用 SHA。
  引用读取遵循 [GitHub Matching References API](https://docs.github.com/en/rest/git/refs#list-matching-references)。
  每类引用响应最多 256 KiB、1024 项；附注标签最多解引用 5 层，每层最多 64 KiB。
  整个仓库文件树最多 2 MiB、4096 项，即使选单文件或目录也受此限制。
  单文件最多 64 KiB，文件累计最多 512 KiB；
  选中的技能符号链接及目录内子模块拒绝导入，不会递归访问其他仓库。
- 所有导入均只返回 `enabled=false/group_ids=[]/category_id=0` 的草稿，不自动写库、不自动上架，
  管理员选站点分类和白名单、编辑确认后，调用原模板保存接口生成独立站点副本。
  以后商店更新不覆盖已导入模板，站点修改不回写仓库；重新导入是新草稿。
- 内置商店收录原创文本示例，不自动扫描私有技能目录，不复制凭据或第三方受限内容。
  在线刷新需该目录先发布到仓库分支；本地实现不包含 Git 推送或商店发布。

## 迁移与回滚

启动迁移仅新增分类表和模板字段，历史模板继续按单技能处理，无需批量改写正文或安装关系。
回滚时保留新增表与字段；旧版本不认识合集和分类管理，不应与新版同时编辑这些模板。
合集已生成的正文仍为普通文本，但恢复合集编辑与导入功能需要重新运行本版本。
本轮只在独立本地 SQLite 预览库执行迁移，尚未部署 zzapi。

## 验证结果

- `model/controller/service/router` 全包测试通过，每包超时 60 秒。仓库链接测试使用固定
  HTTP transport，覆盖引用歧义、固定提交、私有仓库与重定向拒绝、响应及正文限额；
  没有调用真实仓库或供应商。模型与接口覆盖合集装载、分类改名、正文隐藏和管理员权限。
- Classic 28 项相关交互测试与国际化检查通过；Default 42 项测试、类型检查通过。
  两套受影响文件静态检查、格式检查与生产构建通过，最终双模板内嵌 Go 构建通过。
- 本地 SQLite 实例实际通过内置商店导入写作合集，打开编辑器后包含两个独立可编辑技能，
  上架开关关闭、未选分组；检查两套商店及合集编辑器手机布局。
  内置示例的 SHA256、ZIP 损坏、超量条目、限额和未保存草稿不写库均有回归测试。
- 修改文档格式化、新增 4 处相对链接和 `git diff --check` 通过。
  开发索引中既有历史失效链接保留，本轮未扩大修复范围。
- 未实跑 MySQL、PostgreSQL、真实公网仓库和线上供应商；未推送仓库、发布在线目录或部署。
  在线商店需要先将本轮 `skill-store/` 发布到官方 `custom-main` 分支，内置快照可立即离线使用。

「RS2000 德国建站」（serverId 52、hostId 17）核验，三个应用当前均为
`newapi-mao-zzapi:playground-da7c46a4bbac` 且健康。

发布前保存 Compose、环境文件、容器快照、数据目录和 PostgreSQL 自洽备份。
以已提交源码构建唯一镜像；Docker 构建上下文显式保留 `skill-store/packages` 的
Markdown，避免全局 `*.md` 排除规则导致内置技能缺失。
同镜像隔离实例验证合集、分类、导入草稿、普通用户正文隐藏和双模板静态资源，
随后按三个应用顺序更新，首节点先执行新增分类表和模板元数据迁移。
仅替换应用镜像；保留原 Compose 与镜像，回滚保留新增字段和表，不恢复旧数据库。
不更新 maolaoapi，不推送源码或发布在线商店目录。
