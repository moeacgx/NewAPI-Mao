# 技能模板保存校验与反馈修复

## 问题与范围

用户在 zzapi Classic 编辑模板后点击保存，没有看到明确结果。只读检查发现长弹窗
把错误放在最顶部，底部保存时看不到提示；渐进式合集还被错误要求填写合集总说明并保持
技能标题唯一。后端只要求已发布的各子技能具有用途说明，允许不同路径技能同名。

同时检查 Default，确认旧单技能切换按需模式后，资源编辑器生成仅有路径和资源的
`skills[0]`，基础校验先验证隐藏的标题与正文，导致可见字段齐全仍无法提交。

## 方案与兼容边界

- Classic 按后端契约校验渐进式合集：总体说明可空，以稳定身份和主路径区分子技能；
  始终装载合集继续保留旧标题唯一规则。
- 保存错误与操作按钮放在同一个固定反馈区；加载、校验和服务端失败均清楚展示，
  保存失败保留全部草稿；原生表单校验不能让未导入的仓库地址阻断模板保存。
- Default 在校验单技能前使用可见的模板标题、说明和正文规范化子技能，不校验无对应
  可编辑字段的空标题/正文；保留技能身份、路径和引用资料。
- API、权限、计费、存储结构与运行时装载行为不变，不执行数据库结构迁移。

## 验证计划

先用交互回归复现合集空总说明、同名技能、保存错误位置、未导入无效网址及旧单技能
切换按需模式。修复后执行受影响测试、静态检查、格式检查和双前端生产构建。
使用隔离本地页面验证保存成功、失败反馈及草稿保留；若更新 zzapi，则备份当前状态、
逐个更新三个应用容器，保留现有数据库、Redis 和用户模板，不更新正式站。

## 验证结果

- Classic 新增回归先失败，修复后相关 3 个文件共 42 项通过；覆盖空总说明、不同路径同名技能、
  失败聚焦和草稿保留、未导入无效地址不阻断保存。
- Default 旧单技能切按需模式的交互回归先失败，修复后提示词中心 7 个文件共 58 项通过，
  并确认稳定 ID、路径、引用资料不丢失，合集仍完整逐项校验。
- Classic 受影响 ESLint、Default 类型检查及受影响 oxlint 通过；双前端生产构建通过。
- 本地真实浏览器使用独立模拟接口，确认长弹窗中保存与错误提示可见、失败自动聚焦、草稿
  保留，随后重试成功保存空总说明及同名不同路径合集。未连接或复制站点业务正文。
- 线上既有模板原样保存能成功，后端不存在普遍静默失败；此次只修复已复现的前端阻断与反馈。
- 修改文档格式与本次新增的两个相对链接检查通过，`git diff --check` 通过。开发索引中
  81 个既有目标缺失链接未由本次引入，不在本次修复范围。
