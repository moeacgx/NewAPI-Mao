# 技能分类删除

## 目标与范围

提示词中心管理员可以删除技能分类。分类仅用于目录组织，删除时将该分类下模板移到“未分类”，
不删除技能、令牌安装或正文。Default 和 Classic 两套提示词中心均实现此能力。

## API 与事务契约

- `DELETE /api/prompt-center/admin/categories/:id?version=N`，需要管理员权限及正整数版本。
- 成功返回 `{id, moved_templates}`。版本缺失、无效或分类不存在返回业务错误；并发版本冲突返回 HTTP 409。
- 模型事务先锁分类并核对版本，再将引用该分类的模板 `category_id` 设为 0，最后删除分类。
  模板版本不递增，因为分类不影响技能正文或授权。
- 保存模板时对所选分类加共享锁；删除持有排他锁，因此并发保存会在删除完成后失败并提示重新选择。
- 删除不可撤销；备份/恢复整个数据库可恢复分类，普通应用回滚不会恢复已删除行。
- 滚动升级期间，旧节点保存模板没有分类共享锁；所有节点更新完成前不要执行分类删除或编辑分类模板。

## 前端行为

两套模板都在分类管理界面内显示删除确认步骤，确认后调用带当前分类版本的 DELETE。
成功后刷新分类和模板目录；当前筛选分类被删除时回退到全部分类。版本冲突、分类消失和通用错误
在确认界面显示，取消后焦点返回原删除按钮；删除进行中阻止重复提交。

## 验证

- 模型测试覆盖删除移动模板、保留模板版本、保留其他分类、版本冲突、重复删除和旧编辑器提交
  已删除分类时拒绝保存。
- 控制器测试覆盖参数、409、移动数量和重复删除；路由测试覆盖管理员权限。
- Default/Classic 组件回归覆盖确认、成功刷新、筛选回退、错误状态和焦点行为。
- Classic en/fr 删除成功提示采用数量中性措辞，其余语言资源保留本地化文案。
- 跨库测试在 SQLite、MySQL、PostgreSQL 运行分类删除事务；未配置 MySQL/PostgreSQL 测试 DSN 时，
  对应矩阵用例按仓库规则跳过。
