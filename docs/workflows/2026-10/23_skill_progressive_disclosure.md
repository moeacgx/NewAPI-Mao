# 技能渐进式披露实现记录

## 状态与目标

2026-10-23 用户确认由网关完成技能读取，不要求客户端另配 MCP，并取消技能文件原有的
32 KiB 限制。本项在独立分支 `feat/skill-progressive-disclosure-20261023` 实现和验证，
尚未推送、发布或部署；此前线上提示词装载不因此自动升级。

现有技能中心、分类、合集、ZIP / GitHub / 内置商店作为管理与导入入口继续使用。
本次将运行时从全文装载扩展为目录发现、主文件读取、引用文本读取，合集中的技能独立选择。
依据 [Agent Skills 规范](https://agentskills.io/specification)与
[接入指南](https://agentskills.io/client-implementation/adding-skills-support)的分层披露原则。
本实现支持文本指令和资料，不提供服务器端脚本执行环境。

## 模式与数据契约

- `load_mode=eager`：旧空值也按此模式解释，保留每项正文 32768 UTF-8 字节、
  每令牌启用正文合计 65536 字节及合集 2 至 16 项的既有行为。
- `load_mode=progressive`：新建及 Markdown、ZIP、仓库、商店导入默认此模式。
  单项或合集均可使用；合集 2 至 128 项，不拼接成一份全文提示词。
- 每个子技能保存稳定 `id`、`title`、`description`、入口 `path`、主文件 `content`，
  以及 `resources:[{path,content}]`。发布时用途描述必填，同名技能按稳定 ID 区分。
- 单文件最多 8 MiB、单包文本合计最多 64 MiB、总文本文件最多 4096 个（含主文件）。
  入口和资源相对路径最多 1024 UTF-8 字节；拒绝绝对路径、越界、重复路径和 NUL。
- ZIP 上传最多 16 MiB、4096 个条目，声明解压大小合计最多 64 MiB。
  导入仅保留技能目录下支持的文本资料，不执行脚本，不把根目录 README 等普通文件当作技能。
- 新增 `prompt_skill_records`、`prompt_skill_files`、`prompt_skill_chunks`。
  文件使用最多 48 KiB 的 UTF-8 TEXT 分块，避免 MySQL 单列 TEXT 容量限制。
  普通用户摘要查询只取元数据；管理员编辑与导入接口才返回完整内容。
- 管理 API 路径及安装 API 仍沿用提示词中心契约，安装上限为每令牌 8 个包。
  渐进式内容不占用旧全文模式 64 KiB 校验额度，进入模型的已读文本仍计入输入用量。

管理员从渐进式切回全文模式时，页面提示保存将移除引用资料；保存按旧模式限额校验，
事务内清理渐进式记录，保留令牌安装关系。未保存切回时仍保留编辑草稿。

## 网关运行时

覆盖 Chat Completions、Responses、Claude Messages 和 Gemini HTTP 对话接口，
包含最终普通回复和流式回复、普通转发和透传。不扩展 Realtime、图像、音频、embedding 或任务接口。

1. 完成令牌鉴权和实际分组、渠道选择后，网关建立仅供本次路由尝试使用的读取会话。
2. 复制已装载旧普通提示词的请求，启动私有非流式读取阶段。仅声明网关三个读取工具，
   去除客户端工具、MCP 服务、强制工具选择及输出格式约束，避免执行客户端动作。
3. 模型先看到可用技能的名称、用途、所属包、版本和稳定 ID，不包含技能正文。
   目录较大时通过搜索和分页继续发现。
4. 模型调用读取工具，网关返回授权文件页，再请求同一渠道、同一协议。
   最多 8 个模型轮次，每轮最多 8 次工具读取。
5. 没有工具调用时结束读取阶段；达到轮次上限后使用已读资料继续生成。
   私有预览文本与工具调用不发送给客户端。
6. 从原始请求重新构造最终请求，仅装载本次实际读过且重新授权的文件页，
   恢复客户端原有工具、输出格式和流式配置。最终回复仍使用既有 relay helper。

内部工具不新增公开路由：

- `newapi_skills_list`：按名称、描述或包名查询元数据，使用 `query`、`offset` 分页。
- `newapi_skills_read`：按 `template_id`、`skill_id`、`version`、`path`、`offset`
  读取文本；先读 `SKILL.md`，再读已披露的引用路径。每页最多 24 KiB，UTF-8 字节偏移，
  返回 `next_offset`、`total_bytes`、`eof` 与剩余预算。单次客户端请求最多读取 192 KiB，
  重复同一页不重复消耗读取预算，但真实模型调用仍计费。
- `newapi_skills_files`：读取主文件后按 `query`、`offset` 搜索或分页披露引用路径，
  不返回引用文件正文。每页最多 32 条、序列化路径最多 8 KiB。

目录初始元数据最多 64 KiB，过大时首批及后续目录页最多 32 项、32 KiB；
主文件返回的引用目录也分页，避免大量路径挤满上下文。
文件容量、披露预算与模型上下文限制分别生效，不再把文件限制为 32 KiB。

## 权限、重试与可见性

- 发现和读取使用每次请求实际选中的分组，白名单按稳定 `Group.Id` 关联，
  页面仍展示 `Group.Name`；不能以令牌可能使用的分组并集代替实际分组授权。
- 每页重新检查令牌有效性、启用安装、模板发布与版本和分组白名单。
  最终装载前再次检查已读页；卸载、停用、下架或版本变化会阻止继续装载。
- 渠道重试从原始客户端正文重建。旧会话、已读页、私有工具结果及推理签名不跨组复用，
  新分组重新发现目录；客户端自行提交的历史内容不属于网关可撤回的范围。
- 私有读取保留 Responses 加密推理、Claude thinking 签名与 Gemini thoughtSignature / 调用 ID，
  仅用于同一渠道内续轮，不回传客户端。
- 敏感词策略覆盖实际出站的目录、读取结果和最终正文。请求取消会结束后续读取。
- 用户页面继续只显示摘要和安装管理，不增加正文查看入口。
  获授权正文进入上游模型后，无法承诺模型绝不复述或令牌持有人绝对无法获得正文。
- 内部工具不会执行客户端工具、外部 MCP、技能脚本或附件；目标模型必须支持对应协议工具调用。
  不支持时按上游错误处理，不自动回退为整包全文注入。
- 实际装载渐进式技能时，Responses 的非空 `conversation` 和 Gemini 的非空 `cachedContent`
  暂不支持，返回 HTTP 400，不发上游请求、不产生消费。前者会将私有工具结果写入持久会话，
  后者无法在保留缓存指令和工具的同时安全切换到内部读取工具。请使用包含完整历史的
  `input` / `contents`；不直接删除这些字段而丢失用户上下文。
  无技能或只有全文模式模板的请求保持既有行为。此限制依据
  [Responses 会话持久化说明](https://developers.openai.com/api/docs/guides/conversation-state)及
  [Gemini 缓存使用限制](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/context-cache/context-cache-use)。
  现有 Responses relay 清除 `previous_response_id` 的行为没有在本次改变，不能据此宣称支持其服务端历史续接。

## 计费和渠道指标

私有模型轮次与最终生成分别预扣、结算并写消费日志，真实调用增加用量、费用和首字延迟。
每轮使用独立计费会话和请求标识，保留原计费规则版本，按本轮正文刷新输入估算。
余额不足时不发送该轮；后续失败只退回未结算预扣，已经完成的读取轮次不会退款。

消费日志附带 `gateway_skills` 的阶段、轮次、包、技能、版本、路径与读取偏移，
该字段不额外记录正文。现有管理员请求审计或归档配置仍按各自既有策略工作。
渠道指标保留每个上游轮次用量与失败事件序号，内部读取轮次不计为渠道重试；
`retry_count` 按外层真实路由重试统计，最终请求仍保留客户端流式标记。

## 验证结果与边界

- 本地 SQLite 下通过模型、控制器、服务、路由测试；Go 测试使用 `-timeout=60s`。
- Chat 四个组合及 Responses / Claude / Gemini 十二个组合验证普通 / 流式最终输出、
  普通 / 透传、按需披露、原工具配置恢复、签名和加密推理保留。
- 模拟上游使用按次定价，核对各轮真实用量、钱包、令牌余额及消费日志。
  不据此声称四协议逐 Token 定价、所有资金来源或真实供应商全部验收。
- 专项覆盖超过旧 64 KiB 的多页正文、UTF-8 页边界、192 KiB 预算、目录分页、
  未披露路径、卸载、分组变化、取消、余额不足、私有轮次失败、最终失败及非法工具响应。
- 真实鉴权和分发链验证 auto 跨组重试：第一组三轮读取结算后最终生成失败，第二组不在技能白名单，
  仅发送原客户端请求；四个成功调用各扣 100，钱包和令牌均从 10000 变为 9600，失败生成未多扣。
  服务端持久会话 / 显式缓存组合另有先红后绿回归，验证 HTTP 400、无上游调用、余额不变、无消费日志。
- 存储与导入覆盖大文件、独立技能、路径隔离、文本过滤、旧模式转换和事务保留安装。
  数据访问按 SQLite / MySQL / PostgreSQL 兼容设计审查；本轮未连接 MySQL、PostgreSQL 实库。
- Default 共 57 项相关交互测试及类型、静态检查、格式、构建通过；Classic 渐进式、
  中心、合集及语言资源相关测试和静态检查、格式、构建通过。本轮未做浏览器视觉验收。
- Gemini 原生非透传续轮的调用 ID 丢失已有先红后绿回归；`relaykit` DTO 测试与
  `GOWORK=off go build ./...` 通过。
- 最终网关、提示词和渠道指标组合回归通过；根模块使用本地便携 Go 1.25.5 amd64 工具链，
  内嵌两套最新前端产物的完整构建通过。未修改系统 Go 安装或全局环境。
- 8 份修改文档通过 Prettier；新增的 13 个相对链接目标全部存在。对修改文件进行完整链接扫描时，
  开发索引仍有 81 个基线已存在的缺失目标，本项未修改这些历史记录；新增链接无失效项。
- 本轮未访问真实模型供应商，未更新 zzapi 或其他线上容器。

## 迁移与回滚

迁移只新增加载模式字段与三张技能表，不自动转换旧模板。
新旧加载模式可以同时安装；普通提示词继续每次全文装载。
生产升级前需要备份数据库并执行正常迁移，本轮尚未执行生产迁移。

回滚旧二进制前先停用渐进式模板；旧二进制不理解独立文件和按需读取，
不能让旧编辑器保存渐进式模板，也不能把旧界面的显示当作完整数据。
保留新增表与数据，恢复支持此契约的版本后可继续使用；不要为回滚直接删除文件表。

## 跨项目影响评估

NewAPIForDouDi：值得分享目录、文件分块和读取授权设计，能减少多技能全集注入；
应先适配其实际分组、relay 协议和每轮计费流程。

NewAPIModifyByGang：若已有技能中心或令牌提示词装载，值得分享此扩展；
需要适配管理界面、导入器、数据库迁移与网关工具循环，不能直接套用前端补丁。

普通 API 客户端无需更换令牌格式或安装 MCP，但渐进式模板会增加内部模型调用和用量。
未向兄弟项目创建 Issue、PR 或发送消息。
