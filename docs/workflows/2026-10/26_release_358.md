# .358 模型守卫正文来源发布

## 范围

用户明确要求在 #359 合并后发版，再逐个更新 maolaoapi。基线为合并提交 `7fc807e74c01100b230cd2ae2266db3904bbf45c`。本版相对 `.357` 纳入 #359：停止把 faster-model 响应头用于自动模型检测，仅响应正文模型声明参与原有白名单、阈值和关渠流程。

保留 `detection_source` 字段、历史异常记录、接口和通知展示兼容；不回写历史、不恢复已禁用渠道、无新增表结构。两套模板继续使用同一后端，已有模块无需更新。

## 发布门禁

1. 版本 PR 仅更新 VERSION、索引和发行／部署工作记录，最新基线 CI 通过后合并。
2. 在准确合并提交创建 `v1.0.0-rc.10.1.10.358` 附注标签。
3. 等待 Linux 与 Docker 双架构工作流，下载核对二进制 SHA-256，核对镜像版本、revision 和 amd64/arm64 清单。
4. 正式发行后按[生产部署记录](26_maolaoapi_358_deployment.md)逐节点更新，不同时重建多个节点。

## 验证与兼容

- #359 同步 `.357` 后的定向回归、转发包完整测试、go vet、Markdown 格式、独立复核及前后端 CI 全通过。
- 模型守卫仅核对供应商声明，不能证明底层模型身份；仅响应头提供模型时跳过检测。
- 回滚到 `.357` 或更早版本会恢复头部检测，应先评估是否暂停该守卫。已有历史来源字段和数据保持。
- 发布前未做真实供应商收费请求或 MySQL/PostgreSQL 实库业务验收。发行、健康检查和真实业务验收分开记录。
- 本记录为发布计划，最终标签、工作流和资产结果以 GitHub Release 为准。
