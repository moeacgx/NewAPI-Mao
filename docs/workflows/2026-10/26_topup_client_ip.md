# 充值日志恢复订单客户端 IP

## 目标与基线

在 `custom-main` 的 `.356` 基线 `5a9e97849dcbd509955f3a804527ed517a59da16`
上，仅恢复新订单型充值成功日志的客户端 IP。来源是用户创建订单时保存的
`TopUp.RequestIP`，与消费日志使用同一条 Gin `c.ClientIP()` 可信代理解析链。
本次仅核验当前源码和本地测试，没有读取线上日志或配置。

## 根因与历史关系

- 旧 PR #125（`d728fe6cb`）仍未合并，目标是将订单请求 IP 与支付回调 IP 分开；
  三点差异与 `git cherry` 表明它不是当前基线已完整包含的等价补丁。
- 当前基线已有 #132 及后续修复，结算层不再接收回调地址，也不会用回调或补单
  地址填充空 `RequestIP`。
- 后续 #277 明确停止所有充值日志 IP 写入和返回。因此当前缺口是新充值日志也被
  清空，不能直接合并旧 PR，或删除全部历史隐私过滤来恢复显示。

## 范围与契约

- EPay、Stripe、统一支付尝试（含 Creem、Waffo、BEpusdt、OKPay）、旧 BEpusdt、
  Waffo Pancake、免费优惠码和管理员补单共用订单日志入口。
- 写入充值日志时，与消费日志相同：`ForceRecordLogIpEnabled` 优先，否则读取
  用户 `RecordIpLog`；关闭或读取设置失败时不记录客户端 IP。
- 只从订单 `RequestIP` 取值。缺失时保持为空，不查询最近消费或登录 IP，不修改
  已保存订单，不因重试、回调或补单重新采集用户地址。
- 新订单日志在 `other.admin_info` 中保存 `request_ip_source=order_request`
  和对应的 `request_ip`。仅此来源标识与 `logs.ip` 一致时允许保留日志 IP。
  该标识由服务端日志入口生成，不接收客户端 JSON 的标识值。
- 历史充值日志、兑换码和非订单充值日志继续脱敏。已有历史库数据不重写，也不
  根据订单或用户信息重新构造历史 IP。保留原始 JSON 数值精度和损坏字段保护。
- 普通用户与令牌日志只得到允许记录的 `ip`，`admin_info` 仍由原权限逻辑剥离。
  支付回调地址不能写入用户 IP；当前回调运行诊断及独立管理员操作审计保持原契约，
  不大范围恢复旧 PR 的回调参数。

## 安全、数据库与兼容边界

不调整 `TRUSTED_PROXIES`、Gin 转发头配置或 CF 头策略；不改支付验签、支付尝试、
结算、金额快照、返佣、幂等或数据库结构。SQLite、MySQL、PostgreSQL 复用现有
字段和 GORM 路径，无迁移或历史批量操作。

Default 与 Classic 共用后端日志 API，本次只改后端，无前端文件变更。发布前仍需
按部署环境验证可信反代链；本地集成通过不代表线上 IP 链已验收。回滚后新日志也会
重新隐藏 IP，订单和金额不受影响。

## 测试计划与结果

- 订单结算回归覆盖六条支付／补单路径、空／非空订单 IP、用户开启／关闭和强制
  记录，保留金额审计和重复回调幂等测试。
- 真实控制器本地集成从 `RequestEpay` 建单到支付完成／管理员补单，区分订单、
  回调、补单 IP；覆盖可信反代、非可信伪造 XFF／CF 和禁用代理信任。
- 新日志管理员／用户／令牌查询保留允许的客户端 IP；历史日志继续脱敏，不改库。
- 修改前，六条结算路径的用户开启／强制记录场景均失败，预期下单地址实际为空；
  修改后定向模型回归通过。真实控制器六组集成均通过，无支付外呼或实际扣费。
- `go test -mod=readonly ./model ./controller ./service ./middleware -count=1 -timeout=60s`
  通过（含父测试及子测试共 3142 项）。
- `go vet -mod=readonly ./model ./controller ./service ./middleware`、`gofmt`、
  oxfmt 0.57.0、修改文档新增的相对链接检查及 `git diff --check` 通过。
- 只读独立复审通过；没有 MySQL／PostgreSQL 实库验证，没有线上读取或浏览器验收。

## 共享契约与分享评估

日志 API 的新订单 `ip` 在记录开关允许时返回下单地址；历史日志继续返回空值，
支付 API、模型、鉴权、额度和调度契约不变。Default 与 Classic 读取共用日志 API。

- `NewAPIForDouDi`：建议分享“订单 IP 与回调来源分离、尊重记录开关”的行为规则；
  对方日志模型与隐私历史未核验，暂不建议直接移植来源标识和脱敏代码。
- `NewAPIModifyByGang`：同样建议分享该规则和本地控制器集成用例；需要先确认对方
  下单 IP 字段及充值日志入口，不能仅凭同属 new-api 二开直接照搬。
