# 网关 Skills Chat 多候选响应修复

## 现象与根因

2026-10-27，线上 `.355` 节点在 `POST /v1/chat/completions` 的技能读取阶段记录
`技能读取阶段未返回唯一助手消息` 并返回 502。实际运行镜像为
`ghcr.io/moeacgx/newapi-mao@sha256:62fdd34becf5d62ff2444b21bbaa797081be4bc891b78271248cef9d174f5e12`，
版本 `v1.0.0-rc.10.1.10.355`。

Chat 私有读取解析器把上游 `choices` 数量硬编码为必须等于 1。部分上游即使请求设置
`n=1`，仍可能返回多个候选，导致技能工具调用尚未执行就被网关拒绝。

## 修改

- Chat 解析改为在 `choices` 中选择第一个角色为 `assistant` 的有效消息。
- 没有候选或没有任何助手消息时继续拒绝，避免把用户或系统消息当作技能轮次。
- 保留原有工具 ID、工具名称、未知工具和重复调用校验。

## 验证

- 新增多候选选择和无助手候选拒绝回归。
- 运行 `go test ./service -run 'TestGatewaySkill' -count=1 -timeout=60s`。
- 线上日志仅作根因定位，未在本工作项执行生产写入或重放付费请求。

## 兼容性与限制

该调整只影响 Skills 私有 Chat 发现阶段；正式生成仍使用客户端原始请求。若多个助手候选
内容不同，网关固定选择上游返回顺序中的第一个助手候选，以保持一次确定的技能读取轮次。
