# Responses 网关 Skills 未识别 Agent 工具 502 修复

## 现象与定位

2026-10-25，生产 `/v1/responses` 请求在启用网关 Skills 时返回 502；关闭该功能后请求恢复。
服务日志记录私有发现阶段收到 `interrupt_agent`、`list_agents` 工具调用，随后以“未声明工具”失败。

源码路径确认，发现阶段会把原请求工具替换为三种内部技能工具；Responses 解析器虽然能读出
`function_call` 名称，但原逻辑要求名称必须存在于原始请求的工具清单，否则终止整次请求。
现有证据不能确定这些调用来自 Agent 运行时工具、客户端封装还是模型返回的未声明名称。

## 修复与边界

- Responses 原有 `instructions` 保留在前，网关发现阶段指令追加在后，降低原指令覆盖阶段约束的风险。
- 解析 Responses `custom` 声明和 `custom_tool_call` 输出；其调用作为外部调用隔离处理。
- 未识别的客户端调用不会在网关执行，也不会从历史记录推导授权或伪造工具结果。
- 首次未识别调用仍纠偏一次；Responses 纠偏后再次收到未识别调用时，结束可选发现并恢复原始请求，
  避免 502。Chat/Claude/Gemini 的既有连续提前调用策略不变。
- 正式请求保留原始输入、指令和工具配置。该回退可能没有载入网关技能正文，消费日志会写入
  `gateway_skills.discovery_fallback=true`；技能文件列表仍反映实际读取内容。
- 每个已完成的上游轮次照常计费；回退不撤销此前已结算的发现轮次。

## 验证

- `go test ./service ./controller -run 'TestGatewaySkill' -count=1 -timeout=60s`：166 项通过。
- Responses 集成回归覆盖首次未识别工具后成功读取分页技能正文，以及连续未识别后回退。
  检查原始输入与工具配置恢复、私有调用未执行、正文实际读取记录和回退审计标记。
- 协议回归覆盖 Responses 指令顺序和 `custom_tool_call` 识别。
- 生产没有部署本修复，也没有重放真实付费请求；需要通过独立 PR、CI 和发布流程后再做现场验收。

## 已知限制

生产请求的完整工具声明结构尚未取得，因此不能断定具体调用是运行时工具还是声明解析差异。
回退用于保障正常请求可用；若发生回退，需通过消费审计确认技能是否实际读取，不能视为技能已使用。
