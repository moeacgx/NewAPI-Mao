# 管理员管理请求豁免与令牌取密钥限流隔离

## 问题与目标

ApiPanelWatch 获取模型列表失败的现场链路为：批量取密钥返回 429，单条回退同样
返回 429，客户端保留了空密钥并把同步标记为成功，随后 `/v1/models` 返回 401。
上游令牌本身仍启用且未过期。后台取密钥原先与登录等操作共用按 IP 的 CT 桶，
即使是管理员也受默认 20 次 / 1200 秒约束，且不同用户共享出口会相互影响。

本工作项修复 NewAPI 的管理员后台限流及取密钥限流边界；ApiPanelWatch 的错误吞没和空密钥恢复
属于客户端后续修复，不在本仓库内修改，不执行真实渠道同步或生产数据更改。

## 接口与限流契约

- `POST /api/token/:id/key` 与 `POST /api/token/batch/keys` 完成 `UserAuth` 后，
  普通用户共用按用户 ID 的独立取密钥桶。浏览器 Session 与管理 PAT 属于同一用户时共用额度。
- 普通用户默认每用户 60 秒内 60 个请求。批量请求按一次请求计数，原最多 100 个 ID 不变。
  同 IP 的不同用户分别计数，同用户换 IP 或交替两个接口不能绕过限制。
- 有效 Admin/Root 的后台 Session 或管理 PAT 豁免 `/api` 的 GA，以及后台搜索、
  取密钥和明确管理路由的 CT/UC；普通用户仍使用专用额度。这两个取密钥操作不再
  占用匿名登录 CT，所有角色仍只能读取自己的令牌密钥。
- GA 在原有各路由组的位置替换为同一管理员豁免实现，不改变审计/扩展组的无缓存
  中间件顺序；任务插件选项入口补齐同一 GA。GA 豁免在认证前使用相同的真实凭证校验；路由内豁免必须放在认证后，要求已验证
  的后台身份和管理员角色。普通用户、伪造角色头、禁用账户、失效会话不获得豁免。
- 管理路由覆盖渠道、营销活动、通知、扩展、任务插件、归档、模型校验与游戏管理。
  GA 对有效管理员的 `/api` 请求不计数，但个人 `/api/user/2fa/*`（不含管理统计 `/stats`）与
  `/api/user/passkey*` 保留 GA；这些流程不能仅因已有管理员身份而免除保护。
  登录、刷新、退出、验证码、二次验证、
  PAT 签发、个人支付及游戏兑换/下注仍保留各自 CT/AR/UC。`/v1` 模型调用及
  令牌账单接口不变；RootAuth、权限检查、渠道密钥二次验证、请求体上限继续执行。
- GA 识别后台 Authorization 凭证，纯 Cookie 的扩展资源/代理请求仍按 IP 计数。
  不修改扩展 Cookie 认证或模型 API key 语义，也不把模型令牌所有者的管理员角色视为后台豁免凭证。
- 保留现有身份校验和密钥归属校验；控制器响应及专用取密钥限流的
  429 响应禁止缓存。GA 或 UserAuth 更早拒绝的响应不经过本次无缓存中间件。
- 超限返回 429 和 `Retry-After`，Redis 故障保持现有 500 失败关闭语义。
  共享 Redis 的多节点共用计数；未开启 Redis 时沿用进程内计数，节点之间不共享。

## 配置

- `TOKEN_KEY_READ_RATE_LIMIT_ENABLE`：默认 `true`，仅控制普通用户专用取密钥限流。
- `TOKEN_KEY_READ_RATE_LIMIT`：默认 `60`，窗口请求数；非正数回退默认值。
- `TOKEN_KEY_READ_RATE_LIMIT_DURATION`：默认 `60`，单位秒；允许 1–1200，越界回退默认值，
  避免超过进程内限流桶的清理周期。无效整数和越界值均记录配置错误日志。

配置在启动时读取，多实例应使用一致配置。既有 `CRITICAL_RATE_LIMIT*` 不再控制
这两个取密钥接口，其他登录、刷新和安全接口保持原有规则。没有数据库迁移。
回滚恢复旧的共享 CT 行为，Redis 新桶自然到期，不需要清缓存或删除数据。

## 验证计划

使用真实 API 路由、隔离 SQLite、管理 PAT 和 Session 验证 CT 双向隔离、同 IP
不同用户互不影响、同用户跨 IP/凭证/单条批量共用额度、批量上限、归属检查、
无效/缺失/禁用凭证拒绝，以及 GA 和专用限流开关。覆盖 Redis 与进程内模式；
Redis 时间推进验证窗口恢复，不引入固定 sleep。回归测试最长 60 秒。

## 验证结果

- 原实现真实路由复现 CT 耗尽后取密钥返回 429；修复后普通用户、Admin、Root 在
  Redis 与内存模式下均通过双向隔离验证。
- 新增真实路由红测复现同出口 GA 耗尽时 Admin/Root 的取密钥仍为 429；修复后两种
  存储模式、Session/PAT、单条/批量均通过。管理路径验证了请求校验仍执行，
  管理员搜索豁免、普通用户搜索仍受限，Root 权限与渠道密钥二次验证未被绕过。
- 登录、刷新、退出、通用二次验证仍会超限；个人 2FA/Passkey 保留 GA；伪造角色头、
  普通用户、禁用账户、已撤销会话与模型 API key 不获得管理员豁免。
- `go test ./common ./middleware ./router -count=1 -timeout 60s` 通过。
- `go test ./common ./middleware ./router -run 'Test(AdminBypass|AdminManagement|TokenKeyRead|SecurityAuditRoutesApplyNoStore)' -count=2 -timeout 60s` 通过，
  覆盖身份、所有权、计数共享、开关、批量边界、配置归一化、管理豁免、审计路由禁止缓存与重复运行隔离。
- `go vet ./common ./middleware ./router`、修改文档 Prettier、链接存在性与
  `git diff --check` 通过。只读方案审查识别的个人安全流程 GA 和扩展 Cookie 边界已落实。

两套前端调用相同后端接口，无前端改动。跨项目契约影响为有效管理员的后台管理请求
免除上述业务限流，普通用户取密钥从共享 IP 改为独立用户计数；请求、成功响应和所有权语义保持；客户端遇 429 仍应遵循
`Retry-After`，不能继续使用空密钥或把同步标记为成功。已有空密钥需要修复部署后
重新同步补齐。本补丁未改变 ApiPanelWatch 本地记录。2026-09-25 在最新主分支
重新整合，复用已合入的用户取密钥配置，增加管理员豁免并保留后续安全更新。
重新验证及部署结果见本轮 .338 发布记录。
