# 同步任务性能采样与结果留存说明

## 问题与范围

Jev已能返回且消费日志有486输入/70输出，但模型广场没有样本。线上只读查询确认
24小时summary含其他43个模型，无Typesafe-jev；该模型详情groups为空。
根因是同步任务只接入渠道指标，没有调用模型广场独立的perf_metrics采样。
另外，retainResult:false按官方合同仍保留任务账务行；本地遗漏result_discarded公开DTO及Classic说明。

## 实现合同

仅为声明不保留结果的原生同步任务接入模型广场采样，按客户端模型和实际分组记录。
成功结果统计实际输出Token与请求延迟，非流式不伪造首字时间；零输出成功仍计成功次数。
已发送到上游的失败计失败，沿用性能失败过滤规则；鉴权/解码/配置/余额不足、客户端取消、
宿主持久化或结算错误不算供应商失败。异步提交成功不等于模型完成，保持原行为。
任务消费日志记录真实经过秒数，不再因漏填显示小于1秒。

保留任务Insert、资金边界和列表分页；同步官方result_discarded字段，Classic显示结果未保留并说明
已通过API返回。只改Classic展示，Default任务列表不在本次界面修改范围；性能后端两模板共享。
不删除历史任务、不回填不存在的历史性能样本；发布与部署在单独授权后执行。

## 验证计划

真实Gin路由与模拟上游验证按次/表达式成功、零输出、上游错误、无效响应、
配置或预扣失败、取消、失败过滤和异步提交隔离。断言性能summary、详情、次数与费用不变。
Task DTO管理员/用户都返回标记且不泄漏私有数据，Classic普通状态保持。
Go测试超时60秒；更新任务插件技能要求分别验收渠道指标和模型广场性能。

## 验证结果

已完成本地真实 Gin 路由矩阵：4 个同步成功（含 486/70、零输出和超界输出忽略）、HTTP 失败、
畸形响应、Immediate FAILURE、失败过滤、解码/余额/客户端取消隔离，以及 pending 异步不计成功。
模型广场 summary/detail 查询均验证成功率和模型分组；非流式同步任务 TTFT 保持 0，整体延迟用于
TPS。消费日志回归验证 `UseTimeSeconds` 和实际输入/输出 Token。控制器、服务、路由定向测试通过，
均使用 60 秒超时。Classic 结果列兼容测试、8 语言检查、JSX lint、格式检查和生产构建通过；构建仅有
既有依赖过期及大 chunk 警告。

实现同时保留上游错误的安全分类码，避免 `cyber_policy` 等策略响应污染失败率；HTTP 200 却返回 SSE
的协议错误按已发送上游失败处理。Jev 使用官方同步插件能力，必须升级到包含本修复的主程序后才会
出现模型广场样本；插件源码无需改动。Default 页面未修改，Classic 是本次结果说明的唯一前端范围。

任务账务行不会删除，`retainResult:false` 只清理私有结果和凭据；历史调用没有性能样本，修复后不回填。

合并前复核补齐纯文本 HTTP 500 biological 风险提示、Cloudflare `errors[0]` 包裹及字符串
`error` 的性能过滤信息；内部消息先脱敏且不返回客户端。真实路由回归已复现原行为错误计数，
修复后验证策略过滤及普通消息过滤均不增加样本，不影响退款。数字错误码使用十进制字符串匹配。
