# 充值日志不记录或返回 IP

## 问题与目标

2026-09-25，使用日志仍在充值记录的 IP 列展示代理地址。此前修复只禁止支付回调
地址回填，`RecordTopupOrderLog` 仍将订单 `RequestIP` 复制到 `logs.ip`、
`other.admin_info.caller_ip` 和 `request_ip`，并写入 `server_ip`。
本次要求是充值日志不记录 IP，而非更换 IP 来源。

## 范围与契约

- `LogTypeTopup` 新日志的 `ip` 为空，不保存客户端、回调或服务器 IP 审计字段。
- 删除充值日志专用 DTO 和函数参数中的请求 IP，订阅购买共用该日志契约。
- 通用日志写入入口同样过滤充值 IP，覆盖兑换码和其他充值日志调用方。
- 管理员、普通用户和令牌日志查询统一清理历史充值 IP；两套前端及基于查询结果的
  导出均使用同一后端返回值，无需仅在页面隐藏字段。
- 保留金额、余额前后、到账额度、订单号、支付方式、节点名称和版本等非 IP 审计。
- 清理使用原始 JSON 字段，避免新增 int64 金额精度损失；损坏的历史 JSON 不原样
  返回，损坏的 `admin_info` 被移除，其他可解析业务信息保留。
- 保留登录、消费、错误和独立管理员操作审计原有 IP 行为。
- 不修改支付验签、订单状态、幂等结算、额度、订阅、返佣、发票或数据库结构。
- 本次只改变充值日志契约；订单字段和支付诊断日志不在修改范围内。
- 不自动清洗历史数据库；历史记录在读取时脱敏，重新部署旧版本可能再次显示旧 IP。

本契约替代 [旧订单请求 IP 保留规则](../2026-08/30_topup_request_ip_preservation.md)
中关于充值日志继续记录订单 IP 的规定，旧记录仅作历史背景。

## 验证计划

先运行失败回归，再修改实现。覆盖六种充值完成路径、订阅共用日志入口、通用充值
审计写入、管理员与用户历史记录查询，并确认金额审计及其他日志 IP 保留。
运行相关 Go 测试（每包超时 60 秒）、静态检查、文档格式与链接检查。

## 验证结果

- 修复前六种充值完成路径、通用审计写入和三种历史查询回归均失败，确认能捕获旧 IP。
- 修复后上述测试及订阅日志入口通过；原始数据库历史 IP 保持不变，响应中已清除。
- 原始 JSON 数值测试覆盖 `9007199254740993`，清理过程保留精确余额；另覆盖损坏的
  历史 JSON 和错误类型的 `admin_info`，防止其透传旧 IP。
- `go test -mod=readonly ./model ./controller ./service -count=1 -timeout=60s` 通过。
- `go vet -mod=readonly ./model ./controller ./service` 通过。
- oxfmt 0.57.0、本次新增及修改的相对链接和 `git diff --check` 通过。
  开发文档总索引存在历史失效链接，全量链接检查未通过；这些链接在基线中已存在，
  不属于本次修复范围。
- 只读复审通过；未进行生产支付请求、历史数据库清洗、发布或部署。

Default 与 Classic 均读取共用日志 API，覆盖两套模板的表格和详情字段；没有前端
代码变更，也未声称已完成线上浏览器验收。跨项目影响仅为充值日志的 `ip` 返回空值，
上述管理员审计 IP 键不再返回；其他日志和支付 API 契约不变。
