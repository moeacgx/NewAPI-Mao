# 令牌分组迁移保留历史独立分组绑定

## 问题与目标

令牌可能在分组被改为独立分组之前就绑定了多个分组。普通分组迁移仅替换源分组，却在写入阶段重新校验整个令牌，因无关的历史独立分组冲突而整批回滚；预览又没有执行这项校验。

## 范围与契约

- 显式分组迁移的预览和执行使用同一冲突判定。迁移后的多分组绑定包含独立分组时，只有该独立分组在迁移前已处于多分组绑定中，才允许保留历史冲突。
- 迁移不得新增处于冲突中的独立分组；新增冲突时，预览和执行都返回具体令牌 ID，并保持执行事务原子回滚。
- 源分组替换、目标已存在时的去重、顺序和目标倍率保护优先级保持不变。已删除令牌和迁移到 `auto` 的流程不变。
- 普通令牌创建、编辑和鉴权仍拒绝独立分组多绑定；迁移不会修复历史冲突或放宽鉴权。

## 安全与兼容性

仅复用现有 `groups.exclusive` 和稳定 `token_groups` 关系，不新增接口、配置或数据库字段。预览只读；执行在原有数据库事务内更新，失败时全部回滚。SQLite、MySQL 和 PostgreSQL 均使用现有 GORM 查询路径。

## 验证结果

回归测试覆盖历史独立分组冲突下的普通分组替换、目标已存在时的去重和倍率保护，以及迁移新增独立分组冲突时预览与执行均拒绝。`go test ./model -count=1 -timeout 60s`、`go vet ./model`、修改文档的 Prettier 检查和 `git diff --check` 均通过。
