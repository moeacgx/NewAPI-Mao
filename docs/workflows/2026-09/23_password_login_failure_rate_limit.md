# 密码登录失败限流隔离

## 问题与目标

`POST /api/user/login` 当前与注册、注销、密码重置、OAuth、令牌管理和支付等操作
共用按客户端 IP 计数的 `CT` 桶。中间件在进入登录控制器前计数，因此成功登录、
参数错误和其他关键接口都会消耗默认 `20 次 / 1200 秒` 的同一额度。共享 NAT 或
CDN 出口下，一个账号或一类无关操作可以使其他账号的首次登录直接收到 429。

本次只修复密码登录的可用性边界：登录不再消费共享 `CT`，只按失败的密码认证
尝试计数；全局 API 限流、Turnstile、匿名请求体限制以及其他敏感接口的 `CT`
保护保持不变。不修改前端、Refresh、2FA 验证、Passkey、OAuth 或会话签发架构。

## 设计合同

- 密码登录使用两个独立失败桶，默认启用：每个账号和客户端 IP 组合在 60 秒内
  最多失败 5 次；每个客户端 IP 在 60 秒内最多累计失败 30 次。后者限制随机账号
  制造无限键和持续密码哈希开销，又不会回到共享 `CT` 的 `20 次 / 1200 秒`。
- 账号只去除首尾空白，不转换大小写，以匹配现有数据库精确账号查询语义；普通
  账号使用 `account:\0` 域、匿名输入使用 `anonymous:\0` 域，再通过服务端密钥
  执行 HMAC-SHA-256。Redis 和内存键只保存客户端 IP 与摘要，不保存账号原文，
  合法用户名 `__anonymous__` 也不会与匿名槽碰撞。
- 缺失账号或不可解析 JSON 使用匿名身份摘要，防止空参数制造无限键；JSON 解码
  即使留下部分 username 也不得使用该值，避免畸形 password 消耗目标账号桶。
  不存在账号与密码错误使用相同响应和相同失败计数流程，避免账号枚举差异。
- 检查只读取当前失败数；只有参数不完整、账号不存在、密码错误或账号不可用时
  同时记录账号桶和 IP 总桶。成功登录、成功进入 2FA 挑战、数据库错误和会话签发
  错误不计数，也不清除此前失败，避免一次成功凭据抹掉攻击历史。
- 同一客户端 IP 与账号组合同时只允许一个密码认证进入数据库查询和密码哈希。
  在途租约默认 10 秒，请求正常结束立即按随机 token 比较释放；进程或请求异常时
  最多占用 10 秒。每个客户端 IP 同时最多 8 个不同账号进入验证，第 9 个返回
  `AUTH_LOGIN_BUSY`；不同客户端 IP 不共享租约。
- 达到阈值后的下一次请求返回 HTTP 429、`Retry-After` 和稳定错误码
  `AUTH_LOGIN_RATE_LIMITED`。成功登录不清除既有失败记录，避免攻击者用一次成功
  凭据清除攻击历史；但成功本身不增加计数。
- 2FA 第二阶段继续沿用现有 `CT`。密码第一阶段验证成功并签发 2FA flow 时不记为
  登录失败，本次不把多阶段认证合并进同一失败桶。

## 并发与安全边界

失败记录在 Redis 中使用同一段原子 Lua 同时递增账号桶与 IP 桶，在内存模式中
使用同一互斥锁更新两个固定窗口。限流预检查与失败后的记录有意分成两步，避免
成功请求预扣后再跨窗口 `DECR`，造成错误退款或删除其他并发请求的计数。

账号/IP 在途租约阻止同一组合并发进入密码哈希，IP 在途集合把不同随机账号的
并发验证限制为 8。Redis 使用 ZSET 原子清理过期 token、计数和准入；释放时账号锁
必须 compare-delete，IP 集合只 `ZREM` 当前 token，旧请求不能释放新租约。外层
GA、Turnstile 和请求体限制继续承担更粗粒度洪泛保护。

仅按 IP 使用独立 `LI` 桶虽然能消除其他 CT 路由污染，但仍会让共享出口中的账号 A
耗尽账号 B 的登录额度，因此不满足本次合同。账号摘要与 IP 的组合把影响限制在
同一出口的同一规范化账号；分布式 IP 轮换仍需 Turnstile 和外层流量防护处理。

## 配置与兼容性

新增：

- `LOGIN_FAILURE_RATE_LIMIT_ENABLE`：默认 `true`。
- `LOGIN_FAILURE_RATE_LIMIT`：默认 `5`。
- `LOGIN_FAILURE_RATE_LIMIT_DURATION`：默认 `60` 秒，不得超过内存桶清理周期。
- `LOGIN_FAILURE_IP_RATE_LIMIT`：默认 `30`。
- `LOGIN_INFLIGHT_IP_LIMIT`：默认 `8`。
- `LOGIN_INFLIGHT_LEASE_DURATION`：默认 `10` 秒，限制为 `1..60` 秒。

不新增数据库表或迁移。多节点共享 Redis 时失败计数全局共享；独立 Redis 或无
Redis 时仍按节点独立计数，与现有限流拓扑一致。新命名空间不读取、迁移或清理
旧 `CT` 桶，部署后历史 CT 计数继续保护其他敏感接口，但不再阻塞密码登录。

## 测试计划

- Redis 与内存模式均验证：五次账号失败可返回原认证错误，第六次返回 429；同一
  IP 的不同账号累计 30 次失败后也阻断，窗口恢复后重新允许；响应包含稳定 code
  和正数 `Retry-After`。
- 验证成功登录和 2FA 挑战不消费失败额度，失败账号之间互不影响，首尾空白归入
  同一桶而大小写不同账号保持隔离，Redis 键不包含账号原文。
- 验证缺失账号、无效账号和错误密码计数，而数据库错误不计数。
- 验证畸形 JSON 的部分 username 只计入匿名槽，且匿名槽与合法用户名
  `__anonymous__` 相互隔离。
- 并发记录验证 Redis 原子计数和内存互斥更新不会丢失阈值状态；同账号并发请求
  只有一个进入，租约释放后可立即重试，异常租约在 10 秒内自动恢复。
- 路由回归验证耗尽 `CT` 不再阻塞密码登录，同时 GA、Turnstile、请求体限制以及
  其他敏感路由的 `CT` 不发生放宽。
