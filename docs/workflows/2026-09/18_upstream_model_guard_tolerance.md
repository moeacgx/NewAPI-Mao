# 上游模型校验：渠道白名单与连续请求容错

## 目标和范围

在既有外置插件中增加全局渠道白名单与连续不匹配阈值，默认阈值为 2，允许 1 至 100。
白名单按渠道 ID 保存，展示渠道名称和 ID；其中渠道跳过模型校验计数、记录、关渠和该插件通知。
Default 与 Classic 同步提供配置与记录展示。插件升级至 0.2.0，增加专用能力声明，旧宿主拒绝安装新包。

## 数据与请求契约

配置 API 新增 `excluded_channel_ids: number[]`、`failure_threshold: number`，保存继续校验 `expected_version`。
省略新增字段时保留已保存设置，旧配置读取默认空白名单和阈值 2；显式无效阈值、非正数或未知渠道 ID 拒绝。
白名单最多 1000 个渠道 ID。仅 Root 可读取精简渠道选项，响应只含 `id/name/status`，不得包含密钥。
新增 `GET /channels?keyword=&page=1&page_size=50` 查询选项，配置返回 `excluded_channels` 提供已选项名称。
删除渠道保留已保存 ID，页面标记不可用并允许移除，不把同名新渠道当作旧渠道。

用户明确选择同一渠道的所有检测请求共用计数，仅按渠道 ID 持久化；并发请求按数据库事务处理顺序计算。
每个 HTTP 请求对同一计数项只计一次，跨节点共享数据库计数。
响应首次明确不匹配时同步计入；同一流后续匹配不能撤销该请求的不匹配。
只包含匹配模型的请求在结束时清零；没有模型名、不属于启用规则的请求跳过，不增加也不清零。
同一请求的重试若再次访问同一计数项不重复计入，不同渠道分别处理。
配置版本变化使旧计数失效；达到阈值关渠时清理该渠道的计数，人工恢复后从零开始。

每次不匹配都新增记录，字段增加 `consecutive_mismatches`、`failure_threshold`、`channel_disabled`。
历史记录视为 1/1 且已关闭；新记录未达阈值显示累计计数，达到阈值才关闭整条渠道并入队通知。
通知沿用已有 Bot/任务，比较摘要增加连续次数和阈值，不重发旧事件。
计数更新、异常记录、关渠、通知入队在同一事务中完成，失败整体回滚。

## 验证计划

- 配置默认值、旧客户端省略字段保留、白名单增删/未知 ID/删除渠道及 Root 精简查询。
- 两次关渠、阈值 1/100、匹配清零、缺模型跳过、流式多个片段一次请求、先匹配后不匹配。
- 多请求/多节点计数、配置版本变更、请求重复提交、同渠道跨分组/模型共用计数、恢复重新累计。
- 未达阈值不发通知、达到后仅一次通知、事务失败回滚，旧记录兼容。
- 双模板显示名称、多选白名单、阈值输入、记录计数、保存回读、七语与 ZIP 安装能力校验。

本次实现不部署生产或发送真实通知，既有生产配置由后续发布流程迁移。

## 实现和验证结果

模型、服务、Root 接口与双模板配置已完成，插件版本为 `0.2.0`。
匹配请求没有当前版本非零计数时使用只读查询；有计数需清零和不匹配累计仍通过事务及行锁复核，
避免所有正常请求锁住全局配置行。用持有 SQLite 写事务的回归验证只读路径无需等待，未进行吞吐压测。
