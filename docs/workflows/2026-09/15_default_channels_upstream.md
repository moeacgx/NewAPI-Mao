# Default 渠道多 Key 策略上游集成

## 目标与范围

基于 `origin/custom-main` 的 `45ab82100`，逐段接入上游 `d4c26bfb8` 的多 Key 策略编辑修复，仅修改 Default 模板。Classic、任务插件、模型供应商重构和后端接口不在本工作项内。

## 根因与方案

渠道抽屉仅在新建多 Key 渠道时展示随机/轮询策略，编辑已有多 Key 渠道时隐藏；更新 hook 也未发送策略。开放已有多 Key 渠道的策略控件，并在拥有敏感写权限时发送 `multi_key_mode`。

## 接口与安全边界

- 保留现有 `PUT /api/channel/` 接口和后端 `PatchChannel.MultiKeyMode` 契约。
- 只有多 Key 渠道且拥有敏感写权限时才提交策略；单 Key 渠道不发送该字段。
- 不输入新密钥时省略 `key` 与 `key_mode`，避免变更策略覆盖已保存密钥。
- 输入新密钥时继续尊重 append/replace 模式。
- 保留供应商、稳定分组 ID、监控、并发、TokensPro 同步和上游响应模型契约。

## 测试计划

先补回归测试并确认失败，再修改两处逻辑：覆盖随机/轮询互换、单 Key 隐藏、权限禁用与请求裁剪、append/replace 密钥更新。使用真实抽屉和提交 hook，模拟 HTTP 边界并隔离无关图标资产。

执行本模块测试、相关文件 lint、typecheck 和差异检查；完整 Default 构建与全量测试由集成工作树统一执行。单次测试进程限制 60 秒。

## 验证结果

- 原实现：6 项新增回归中 5 项失败，原因均为已有多 Key 渠道没有策略控件；单 Key 保持隐藏的用例通过。
- 仅开放控件：4 项失败，精确指出实际 PUT 缺少 `multi_key_mode`；权限禁用和单 Key 用例通过。
- 补齐提交字段：6 项新增回归和 8 项既有渠道契约测试全部通过；格式化后的最终复跑为 14/14，耗时 16.55 秒。
- `bun run typecheck` 通过；受影响的三个 TypeScript 文件限定 lint 通过。
- 测试只隔离与策略无关的供应商图标资产，HTTP 返回显式提供渠道、分组、供应商与验证方式 fixture，其余抽屉、表单和权限判断使用真实实现。
- 真实抽屉渲染暴露既有告警：API Key 的 `FormDescription`（`p`）内包含 `div`，原代码运行时也出现；本修复未更改该区域。
- 没有新增 i18n key；继续使用已有策略、随机、轮询和权限说明。
- 三个 TypeScript 文件已用仓库 oxfmt 配置检查版权头之外的格式，文档已格式化，`git diff --check` 通过。
- 全量 Default lint/test/build 由主集成工作树统一验证，本工作树未执行生产部署或后端测试。
