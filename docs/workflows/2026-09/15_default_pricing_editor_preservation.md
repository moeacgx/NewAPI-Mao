# Default 价格编辑器历史规则保留

## 目标与方案

Default 时间范围修复使部分历史表达式无法安全转成可视化条件。编辑器原先将解析失败的规则当作空数组自动回写，导致仅打开页面就清空请求倍率。本项保留无法解析的原始规则，并覆盖模式往返，防止规则丢失或重复乘入主体。

- 可视化自动回写仅在规则可解析时执行。
- 未修改的原始表达式使用传入的计费主体和规则边界，切换模式不重新猜测未知条件的归属。
- 初始化按模型标识完成一次，避免首次模式切换触发二次初始化和重复拼接。
- 阶梯、阶梯条件、请求规则组、请求条件使用当前草稿的稳定标识，添加时生成新编号，删除时同步移除对应标识；输入变化不影响标识，标识不写入配置。
- 时间范围文案改为 `Time range` 并说明同日与跨午夜关系。翻译键由集成工作项统一维护。

## 契约与范围

只改 Default 编辑器，不涉及 Classic、后端接口、存储格式、额度计算或生产配置。保留 `request_rules` 权威跟踪与未知条件原文。合法比较边界（如 `hour < 24`）不因函数返回值域而被错误拒绝，表达式解析器的兼容修复由主集成工作项管理。

新增翻译键：

- `Time range`
- `Start ≤ end: within the day; start > end: across midnight`

## 验证

先通过真实组件复现：打开未知条件及同日 `||` 历史规则时，原实现自动触发回写并令复杂表达式提示消失。

修复后 6 个真实组件用例通过：两类历史规则打开及模式往返保留原文；四类列表编辑、删除前项、再新增后保留幸存行输入节点、草稿值和编辑焦点。

`bun run typecheck`、改动文件定向 lint、`bun run build` 和 `git diff --check` 均通过。新增测试在 60 秒上限内完成。没有执行生产操作。
