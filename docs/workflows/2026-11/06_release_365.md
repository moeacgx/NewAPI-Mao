# .365 令牌分组上限发布与 zzapi 更新

## 目标与范围

用户授权发布新版本、更新 zzapi，并允许使用本地冒烟验证功能。最新发布版本为 `.364`，本次发布 `v1.0.0-rc.10.1.10.365`，纳入 PR #386 的令牌分组上限修复；不修改 maolaoapi 部署。Default 和 Classic 同步覆盖设置入口、保存、选组限制与提示。

## 本地验证

- 两套真实生产构建通过：Default Rsbuild 14.3 秒，Classic Vite 85 秒。使用已有 Node CLI 和依赖，没有安装包；Classic 的 Browserslist、lottie eval、大 chunk 提示不阻断构建。
- 使用隔离 SQLite 和实际 Go API 完成 18 项检查（17 项业务检查及进程清理），通过 HTTP 初始化和管理员登录，设置上限 3→2→3，验证配置落库、合法创建、超限 code/ID/重复项/尾逗号拒绝、编辑失败保留原值、非法 0 拒绝。
- 历史三分组令牌在上限 2 时访问 `/v1/models` 返回 403 和明确超限文案；上限改为 3 后同一密钥恢复 200。隔离库无真实上游，返回空模型列表，不代表模型推理验收。
- 冒烟仅通过 Go overlay 把监听地址限制到 `127.0.0.1`，业务代码不变；独立工作目录与环境隔离生产数据库、Redis 和 `.env`。临时进程已停止，端口 13985 无监听。证据保留在本地 `.git/smoke385/run-20261106-002528/`，不提交测试密钥和数据库。
- 前轮控制器令牌相关 50 项、Default 32 项、Classic 5 项测试以及类型/静态检查通过。功能 PR 的远端前后端 CI 通过。完整实现边界见[令牌分组上限](05_token_group_limit.md)。

## 发布与部署计划

1. 合并经过验证的 #386，独立版本 PR 仅更新 VERSION、本文和文档索引；准确提交通过 CI 后打新附注标签，不移动旧标签。
2. 验证 Linux 两架构资产与 checksums，及 GHCR 版本镜像的架构、版本、revision 与 digest。
3. CloudSSH 精确定位德国 RS2000 的 zzapi 三应用节点；当前现场为 `.362`，主节点端口 18097，从节点 18098、18099，PostgreSQL 和 Redis 共享。实际节点角色以容器配置为准。
4. 在 zzapi 私有目录备份 Compose、环境、容器配置、数据目录和 PostgreSQL dump，核验备份可读性与校验和；只更新三个应用服务，保持环境、挂载、端口及节点角色，不重启数据服务。
5. 逐节点检查健康、版本、未登录管理接口、页面静态资源和启动异常；最终核对公网状态。功能写入冒烟使用本地隔离数据，不向业务库新增测试用户、分组或令牌。

## 升级与回滚边界

本次分组上限修复无新增表。zzapi 从 `.362` 跨版本升级，包含 `.364` 的工单通知回执表和模板预览能力，启动可能执行对应迁移；备份必须在首次新节点启动之前完成。旧通知无回执不补标，历史 Auto 快照继续已有截断规则。

应用失败时使用备份的原 Compose 和镜像恢复节点，保留新增表，不自动恢复或删除业务数据。数据库恢复属于独立操作，不能因回滚应用而覆盖更新后的业务记录。备份校验不等于恢复演练。

## 共享契约与分享评估

超限创建/编辑返回明确业务错误，历史显式多分组超限仍为 403 但正文更清楚；密钥格式、模型 ID、分组稳定标识和计费不变。NewAPIForDouDi 与 NewAPIModifyByGang 均可在确认存在同类多分组问题后参考修复，需适配各自配置和归一化逻辑；未向兄弟仓库发送消息。
