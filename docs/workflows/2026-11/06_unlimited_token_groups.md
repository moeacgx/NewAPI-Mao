# 令牌分组默认不限制

## 目标与范围

用户要求将令牌分组数量的默认值从 5 改为不限制，并发布新版本。同步覆盖后端、Default 和 Classic 的分组配置、令牌创建与编辑、鉴权和自定义 Auto 快照。

## 配置契约与实现计划

- `MaxTokenAutoGroups` 默认值改为 `0`，`0` 表示不限制数量；正整数仍表示最大可选分组数。负数、小数、空值、非数字和超出整数范围的值拒绝保存。
- `GET /api/token/auto-groups` 的 `data.max_count` 原样返回 `0`；前端不能把 `0` 回退成 5、显示“最多 0 组”或截断为空列表。
- `PUT /api/group/details` 的 `option_updates.MaxTokenAutoGroups` 仍提交数字字符串。Default 的可视化/JSON 模式和 Classic 的可视化/手动模式均接受 0，并明确说明“不限制”。
- 数量校验和 Auto 快照截断仅在上限大于 0 时执行。权限、分组身份解析、去重、禁止 Auto 混选、渠道选择顺序、重试预算及计费契约保持不变。
- 不迁移数据库，不改历史令牌。缺省站点使用 0；管理员以前明确保存的 5 或其他正整数继续生效，可手动改为 0。
- 回滚到旧版前，须将已保存的 0 改成旧版支持的正整数，并检查已有令牌是否超出该上限；旧版不理解 0 的新含义。

## 验证计划

- 后端覆盖 0 配置读写、非合法值不改变持久化状态、超过原 5 组的显式/Auto 创建与编辑、鉴权、权限筛选和正数上限回归。
- Default 覆盖设置保存/回显、显式选组与 Auto 快照在 0 下不截断、正数仍限制、七语言文案、类型检查、定向静态检查和生产构建。
- Classic 覆盖两种设置模式、选组交互、0 与正数上限、语言文案、定向静态检查和生产构建。
- 使用隔离 SQLite 和实际 HTTP 接口进行冒烟测试，不调用真实上游模型。
- 发布使用新版本号与不可变标签，核对 CI、Linux 两架构资产和 GHCR 镜像构建结果。
