## 方案与安全边界

- 本地脚本核验最终提交与冻结 raw 来源，按允许增量合成，未冻结配置默认拒绝构建。
- 安装前、每次安装/前端构建/回归后及 Go 编译前后核对全文件集合与摘要；
  仅允许两套前端明确的依赖目录、dist 和三个 tsbuildinfo 生成文件，拒绝新增未登记源码。
- 在新目录重新构建 Default、Classic 和 Linux amd64 程序，冻结源码与资源清单。
- 远端准备新镜像和本轮新备份；所有私有内容只留远端 0700 目录，不输出环境值或数据库内容。
- 发布前必须有绑定本轮配置、产物、镜像与脚本摘要的独立审查和隔离验收记录。
- 每次仅改变一个应用的 Compose image；保留排序后的完整环境键值、端口与挂载。
- 逐节点验证健康、版本、镜像、静态入口及 MCP 未认证边界，同时保持 PostgreSQL/Redis 容器身份和启动时间。
- 失败立即停止后续节点，并尝试回退当前节点到固定 money 镜像，核验回退健康、版本和运行配置。
- 不依赖任何旧验收容器；不恢复数据库覆盖发布期间产生的业务数据。
- 当前 Default 已满足目标，不发送重复写请求。若后续确需调整主题，由协调者安排既有 Root
  登录会话调用 `PUT /api/option/`，再逐节点检查同步；禁止导出凭据、直接 UPDATE 数据库或创建生产测试账号。
