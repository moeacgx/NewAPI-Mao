# .364 工单通知与格式编辑发布

## 目标与范围

用户授权发版。远端最新已发布版本为 `v1.0.0-rc.10.1.10.363`，标签指向 `20665e8c70495097f83efbc5db642ead81050268`；源码 VERSION 仍为 `.362`，因此本次发布新版本 `v1.0.0-rc.10.1.10.364`，不覆盖任何已有标签。基于 `custom-main` 的 `bf1ad7e9132a21846e5f5288004e635001d4a8ec`，相对 `.363` 仅增加 PR #375。

- 工单管理人工回复后，异步编辑 Telegram 原通知为「✅ 已回复」并保留原文，成功立即释放后台跟踪。自动确认、单独改状态不触发，用户再次追问生成新的未回复通知。
- 独立保存原消息位置，不受最近五条投递历史清理影响；失败有限重试。跟踪记录最多保留三天，停用或删除规则立即清理所属记录，发送中的旧回包不重建已清理关联。
- Default 和 Classic 通知中心增加 Telegram 格式工具栏、emoji/变量插入及在线样例预览；新默认模板使用 emoji、加粗、正文引用，自定义模板保留。
- 本次版本 PR 仅修改 VERSION、本记录与开发文档索引，不改业务代码。主工作区的节点恢复记录和未跟踪技能目录不纳入发布提交。

## 契约、升级与回滚

新增 GORM 表 `ticket_notification_messages` 和 Root 接口 `POST /api/notification/preview`。回执保存消息 ID、规则归属及原 HTML，不保存 Bot Token；预览不读取实际工单、不投递消息。预览、保存和发送共用 Telegram HTML 白名单与长度校验。原工单公共接口、权限、路由及计费契约不变。

升级前已发送消息没有回执，无法补标；三天清理后再回复也不再编辑旧通知。历史不合法自定义 HTML 需调整，精确旧默认模板自动升级。主节点启动执行新增表迁移，生产升级前需按现有运维流程备份数据库。回滚至 `.363` 时保留新增表，旧程序不再自动标记；不删除工单或群消息。

本次仅发布 GitHub Release 和 `ghcr.io/moeacgx/newapi-mao` amd64/arm64 镜像，不更新生产容器、不执行生产迁移、不调用真实 Telegram。
