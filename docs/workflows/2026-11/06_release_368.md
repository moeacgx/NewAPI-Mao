# .368 支付会话恢复与跨域等待提示发布

## 目标与范围

版本 `v1.0.0-rc.10.1.10.368` 基于已发布的 `.367`，修复审查发现的两个回归：

- Classic 支付请求抑制通用错误提示时，明确失效的会话未被清理；
  现将认证处理与提示分离，刷新 401 或 `409 AUTH_SESSION_MISMATCH` 仍重新登录，
  临时刷新错误保留登录态。充值、订阅和历史订单重试共用拦截器。
- 共享 API CORS 显式暴露 `Retry-After`，使可信跨域前端可以显示支付等待秒数；
  保留允许来源、凭据及未授权来源的拒绝规则。

本次仅发布代码与产物，不包含生产部署；不包含独立分支上尚未合并的技能运行时。
开发记录见 [Classic 支付限流提示](06_classic_payment_rate_limit.md)。

## 验证与已知限制

- 后端 `middleware`、`router`、`common` 全包测试通过，超时限制 60 秒。
- Classic 相关 44 项测试通过，含会话恢复、缓存与支付提示；新增 6 个失效会话用例先复现失败再修复。
  静态检查、格式检查、生产构建通过。
- Default 认证处理已独立于错误提示抑制，无需修改实现；支付与认证相关 23 项测试通过。
  共享 CORS 修复同时适用于两套模板。
- CORS 6 个顶层测试通过，覆盖可信来源的实际 429 响应暴露等待头及不可信来源拒绝。
- 扩展 OAuth 绑定测试的 11 项本地存储断言失败，在 HEAD 原实现上同样复现；
  属于已知既有问题，未宣称这组测试通过。未执行真实支付商请求。
- PR CI 通过后合并，标签发布触发 Linux 双架构二进制和 GHCR 多架构镜像构建；
  发布后在 Release 中登记工作流、资产校验和镜像验收证据。

## 兼容、回滚与分享评估

无数据库迁移、新配置、依赖升级或支付请求字段变更。保持 `.367` 的查询限流隔离规则，
不改变订单生命周期、模型、API Key、用量、价格和扣费契约。
回滚 `.367` 会恢复静默支付会话失效处理和跨域等待头缺失的问题。

NewAPIForDouDi：若沿用同源 Classic 拦截器，值得核查提示抑制是否绕过登录态清理。
NewAPIModifyByGang：若支持跨域钱包前端，值得核查 `Retry-After` 的浏览器可读性。
两者均应先检查自身实现再移植；本轮不创建跨项目 Issue 或 PR。
