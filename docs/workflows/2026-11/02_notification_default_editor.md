# Default Telegram 通知格式编辑器

## 目标与范围

仅修改 Default 通知中心，Classic 由独立工作项处理。保留 HTML 模板为原始数据，允许自定义 emoji、前缀及全部正文布局；增加光标格式工具栏、显式工单预设和服务端样例实时预览。

## 方案与接口

- 加粗、斜体、下划线、删除线、普通与可折叠引用、行内代码、代码块、剧透、链接和常用 emoji 直接插入或包裹选区，操作后恢复编辑焦点。
- 工单预设只有点击时替换，加载历史模板不会覆盖自定义内容；既有变量插入继续工作。
- `POST /api/notification/preview` 接收 `event_type`、原始 `template` 及首个接收目标的 `mention_user_id` / `mention_name`，成功返回 `data.html` 和 `data.text_length`，失败返回 `message`。
- 编辑防抖 300 毫秒；切换模板、事件或提及时隐藏旧结果，取消旧请求并忽略其响应。预览不发送 Telegram 消息。

## 安全与兼容性

前端只把 Telegram HTML 白名单节点映射为 React 元素，不使用 `dangerouslySetInnerHTML`；仅允许 HTTP、HTTPS、TG 和 mailto 链接，拒绝任意事件属性、脚本和样式。服务端继续负责模板变量和格式的最终校验。保留现有保存、权限、事件切换及业务标识契约。

## 验证计划

RTL 覆盖选区格式插入、焦点恢复、显式预设、实时预览成功/失败与请求竞态；安全用例验证脚本、属性和危险协议不能进入 DOM。运行通知中心定向测试、七语言检查、typecheck、定向 lint、Default 生产构建和差异检查。验证结果完成后追加。

## 验证结果

- 本机没有 Bun 可执行文件，使用已安装依赖的 Node 入口等效运行脚本；没有安装或更新依赖。独立工作树的 `web/node_modules` 是指向主工作区现有依赖的 Junction。
- 通知中心定向 Vitest：7 个文件、22 项测试全部通过，覆盖格式插入、鼠标及键盘焦点、预设保护、服务端样例请求、即时隐藏旧预览、失败提示、乱序响应、事件与提及切换、安全 HTML 和七语言译文。
- `tsgo -b`、通知中心定向 `oxlint`、修改文件 `oxfmt --check`、`git diff --check` 均通过；Default `rsbuild build` 成功。
- 按 i18n-translate 技能使用临时 `add-missing-keys.mjs` 脚本写入七语言的 22 个新键，随后执行同步脚本，临时脚本已移除；同步同时把原先位于文件尾部的 6 个已有分组标签键恢复字母排序，译文未变。
- 本项只验证 Default 前端和模拟的 API 契约；实际 Telegram 投递及后端预览校验由主工作项验收。页面模拟 Telegram 排版，折叠引用与剧透可交互，具体字体与 Telegram 客户端可能不同。

## 审查修复：预览错误留在编辑区

默认 HTTP 客户端会为业务失败和传输失败弹出全局错误提示，取消旧预览请求也会进入该错误拦截器。编辑过程中不完整的 HTML 或变量属于预览面板负责展示的状态，不能每次防抖都向全局弹出重复提示。预览请求应同时设置 `skipBusinessError` 和 `skipErrorHandler`，保留原始拒绝结果给预览面板；保存及其他 API 的提示行为保持原有契约。

回归通过真实默认 HTTP 拦截器和可控网络 adapter 验证：业务校验失败、网络失败在面板显示错误且无全局 toast；旧请求被取消时只展示新预览且无全局 toast。先确认原实现能复现失败，再修复并运行定向测试、类型及 lint 检查。

修复前这 3 项用例分别复现业务错误、网络错误和 `canceled` 全局提示。修复后通知中心 8 个文件、25 项测试通过，类型检查、定向 lint、格式及差异检查通过；本次不重复构建。
