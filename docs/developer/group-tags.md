# 分组标签（MAO-6 / ALHE-113 P2）

## 目标与范围

Classic 后台「分组与模型定价设置 → 分组标签」维护标签。Default 在
`/system-settings/billing/group-pricing` 的分组定价页提供独立「分组标签」模块；
沿用系统设置原有路由门禁，不扩大页面访问权限。管理员可创建、编辑、删除标签，
配置名称、说明、排序、多个 Logo 和名称匹配词，并绑定已有分组。
两套模板的令牌创建和编辑可按标签筛选候选组，分组管理表也提供标签过滤。
Default 补齐范围和实际验证见 [P2 实施记录](../workflows/2026-11/11_default_group_tags.md)。

## 数据与接口契约

- `group_tags` 保存标签；`icons` 在数据库中存为 TEXT JSON，API 中为有序字符串数组。
- `group_tag_bindings` 以 `(tag_id, group_id)` 为联合主键。同一分组可属于多个标签，
  所有关联使用稳定 `Group.Id`，页面展示当前 `Group.Name`，不改变 code、历史 alias、路由或计费。
- `GET /api/group/tags` 返回所有标签，`POST /api/group/tags` 创建，
  `PUT /api/group/tags/:id` 完整更新单个标签，`DELETE /api/group/tags/:id` 删除标签及关联。
  四个接口均沿用分组管理的 AdminAuth 权限。
- 请求字段：`name`（1–64 字符）、`description`（最多 512 字符）、`sort_order`（整数，
  -1000000 至 1000000）、`icons`（最多 6 个，每个最多 2048 字符）、`group_ids`（最多 10000 个正 ID）、
  `match_keywords`（最多 32 个，每个最多 128 字符）。空 `icons` 使用默认图标；空 `group_ids` 允许先建标签。
  匹配词和 Logo、ID 均会去空白并去重；不存在的分组拒绝保存。
- 返回标签包含 `id/name/description/sort_order/icons/group_ids/match_keywords`；按 `sort_order,id` 排序。
- `/api/user/self/groups` 和兼容的用户分组出口保留原 `data` 形状，追加 `group_tags`。
  仅下发与当前可用分组有交集的标签，关联 ID 也裁剪为该交集；不扩大选组权限。

示例：

```json
{
  "name": "国产模型",
  "description": "DeepSeek 与 Kimi 可用分组",
  "sort_order": 10,
  "icons": ["DeepSeek.Color", "Moonshot", "https://cdn.example.com/logo.png"],
  "match_keywords": ["国产", "DeepSeek", "Kimi"],
  "group_ids": [311, 371]
}
```

## 安全与生命周期

- Logo 允许 LobeHub 名称（如 `OpenAI`、`Claude.Color`）或不含用户名/密码的 HTTP(S) 绝对地址。
  不接收脚本、HTML、data URL 或任意 SVG 文本。复用供应商 Logo 渲染器，浏览器加载图片、
  不发送 Referer，失败使用兜底；后端不下载图片。
- 标签仅用于分类展示。标签切换不更改已选分组、顺序、独立分组互斥、倍率保护、auto 或继承语义。
  `auto` 无实体 ID，不能绑定标签，在筛选中保留可达入口。
- Default 令牌表单在选择器上方显示标签大卡片（按抽屉自身宽度用容器查询：窄于 `@md` 为 2 列、之后 3 列，
  长名称两行截断且不产生横向滚动；卡片名称带该标签可选分组数量），选组浮窗内不再重复标签按钮。
  点击或用键盘激活（Enter/Space）标签卡片会切换标签并立即打开选组浮窗；Esc/点击外部关闭后焦点回到该卡片。
  有标签时不再显示独立的「选择分组」按钮：「全部分组」和各标签卡片是选组浮窗的唯一入口，浮窗锚定在卡片区域下方；
  没有标签时仍显示原选择器。已选单个具体分组或全局 Auto 以带名称与说明的简洁条目展示，右侧「移除」按钮清空该选择，
  不增加第二个触发器；2 个及以上具体分组见下方「Custom Auto」有序列表。重开抽屉时标签筛选回到全部。
  选组浮窗中的 Auto（自动选择）只在「全部分组」下排第一位，命名标签页（含浮窗打开时切换）不显示；搜索把 Auto 过滤掉后不会强制保留，
  已选 Auto 与提交语义不变；无标签的普通选择器仍把 Auto 放首位。浮窗高度受可用视口高度限制，选项在其内滚动，搜索框保持可见。Classic 的 Auto 排序规则相同。
  标签按当前用户分组 ID 取交集，只读
  `/api/user/self/groups` 的顶层 `group_tags`，不会调用 `/api/group/tags`。
  切换标签清空选组搜索词；当前选中分组名称仍从完整选项解析，筛选不清除已选值，
  标签仍只筛选候选，不改变已选分组与顺序。
- 普通选择器选中 2 个及以上具体分组时，两套模板显示「Custom Auto」有序优先级列表（序号、拖拽、
  上移/下移、移除），线路格式保持显式 `group`/`group_ids`/`group_mode=explicit`，不转为 `auto`；
  显式 Auto 的 `auto_groups` 编辑器不变。详见
  [令牌分组卡片与优先级列表](../workflows/2026-11/18_token_auto_group_cards.md)。
  标签删除或不再有可用分组时回到全部，分组名称刷新不会改变稳定提交值。
  管理表保留空标签与「未分类」，筛选后的编辑仍更新完整分组集合，不丢弃隐藏行。
  管理模块 CRUD 后刷新管理标签及用户分组缓存；分组配置保存后刷新标签，以获取自动匹配及删除清理结果。
  请求失败保留标签编辑草稿或删除确认，允许重试；保存期间禁止取消草稿。
- 没有标签时保持原有选择方式。令牌窗口提供「全部分组」和有可用分组的标签，隐藏空标签与
  「未分类」；未绑定分组和 `auto` 仍可从「全部分组」选择。当前标签失效时回到全部。
- Classic 令牌点击标签直接打开选组浮窗，当前标签可再次点击重开；有标签时不显示重复添加按钮；标签列数同样按所在窗口自身宽度（容器查询）而非视口决定。
  草稿允许自动/独立分组与其他组一起选择并保留顺序，保存前才检查冲突，提示显示名称与
  移除其他组或单独分配令牌。冲突不发送请求、不清空草稿；后端独立分组约束和合法提交契约不变。
  详见 [交互修正记录](../workflows/2026-10/01_token_tag_picker_flow.md)。
- Default 和 Classic 创建或编辑渠道时，可以点击标签卡片，在浮窗内搜索并勾选该标签下的分组。
  「全部分组」包含未绑定标签的分组，切换标签保留已选项。没有可用标签时，仍可直接打开分组选择器。
  渠道表单展示当前分组名称，按稳定 ID 匹配标签，并沿用原有 `group` 和 `group_ids` 保存契约。
- 后台分组管理保留「未分类」和空标签，筛选器使用紧凑布局。
- 标签编辑支持保存多个匹配词，按任一词对当前分组显示名称进行不区分大小写的包含匹配，名称缺失时才回退 code。
  保存时会把现有命中的分组去重追加到绑定；之后新建或改名分组在分组配置保存事务中自动追加。
  创建和更新响应的 `group_ids` 在事务内读取最终实际关联，包含规则自动追加的分组。
  匹配关联只增不减，移除关键词或改名失配不会自动解绑既有绑定，避免误删手工配置。
- 标签保存、标签删除和分组配置保存，在事务内任何业务读取前共同写锁定
  `options.__group_tag_write_lock` 固定内部行，锁随事务提交或回滚释放。
  该行不属于业务配置，不能删除或作为分组选项修改；进程内互斥仅用于本地协调。
  锁顺序为固定锁行 → 实体分组 → 业务选项/标签/关联；后续自动匹配与删除清理均持锁执行。
  固定行的 UPSERT 先于任何一致性读，覆盖尚未存在的标签与分组，避免多节点同时新建时
  双方读不到对方、漏绑，以及删除后再插入孤儿关联。SQLite 使用事务写锁；MySQL/PostgreSQL
  使用固定行写锁与 `lockForUpdate`，不依赖进程互斥或仅锁当前存在的业务记录。
- 前台创建/编辑令牌仅使用标签筛选，不包含标签管理操作。新建、编辑、删除标签仅在后台
  「分组与模型定价设置 → 分组标签」中提供。标签卡片统一 Logo、名称和数量槽位；
  长名称最多显示两行并保留完整标题，多 Logo 可分两行组合，避免相邻卡片上下错位。
- 分组改名或迁移 code 无需重绑；删除分组时在同一事务清理标签关联。
  删除标签不删除分组或更改令牌。旧分组配置接口不写标签，因此旧客户端保存不清空标签。
- 新表加入串行和并行迁移清单，使用 GORM、TEXT 和普通关联表兼容 SQLite/MySQL/PostgreSQL。
  回滚应用时保留新表、`match_keywords` 列和固定内部锁行；旧版本不会执行新增的规则匹配。
  多节点滚动发布期间，仅新版本参与共同锁协议，完整并发保证在所有写入节点升级后生效。
  `.345` 经用户授权逐节点上线，实际验证与回退边界见
  [生产部署记录](../workflows/2026-10/01_maolaoapi_group_tag_keywords_345_deployment.md)。

## 验证方法与边界

- 后端：CRUD、非法输入、更新回滚、空标签、多 Logo、按权限裁剪、分组改名/alias、删除清理；
  创建/更新响应包含自动匹配的实际关联；SQLite 独立连接验证并发新增规则与分组、删除标签
  与改名、删除分组与新增规则均不漏绑或产生孤儿。使用 SQLite 确定性测试，并检查 SQL
  不依赖数据库专有语法；MySQL/PostgreSQL 并发与迁移未实跑，不把 SQLite 结果视为三库验证。
- 双模板：标签按钮键盘操作、多 Logo/URL、空态、切换保留跨标签多选、auto/独立分组互斥、
  编辑已有令牌和实际提交仍使用原 ID/code；管理绑定展示名称与 code 不同的数据。
- 渠道表单：验证显示名称与 code 不同时可以跨标签多选，新建提交和编辑回显沿用原 ID/code，
  没有标签时能正常选择，手机窄屏中能滚动列表并使用保存按钮。
- 执行受影响测试、涉及文件 lint/格式化、双模板构建、Markdown 链接与差异检查。
  Windows 环境若兼容测试包装器的 60 秒超时不足以装载依赖，可直接以前台 Vitest 命令收集完整结果；
  不把超时或未收集结果记作通过。
  实际执行结果见 [MAO-6 验收记录](../workflows/2026-09/27_group_tags.md)；未运行的数据库或线上验证不得视为通过。
- 标签隐藏、关键词绑定和紧凑布局的复验见 [标签易用性修正](../workflows/2026-10/01_group_tag_usability.md)。
