# Classic 当前连接与令牌使用状态

## 目标与范围

在 Classic 使用日志顶部显示当前用户进行中及最近结束的请求，结束记录保留 5 秒。桌面最多 3 张卡片、手机最多
3 条紧凑连接行，其余通过抽屉按 10 条分页查询。令牌页展示去重后的活动令牌数量与每个令牌的
活动请求数，支持筛选正在使用的令牌。Default 本次不接入页面。

### 连接卡片视觉与手机布局

- 桌面采用模型图标、状态胶囊、独立耗时区和协议标签；模型图标复用现有模型名识别规则，
  不以入站协议推断实际模型厂商，也不暴露真实上游。未知模型使用通用图标。
- 桌面预览按宽度固定为两列或三列；只有一条连接时仍占一个卡位，不随连接数量拉满整排。
  手机继续采用紧凑单行；抽屉内一列铺满可用宽度。
- 手机每条默认只用一行显示图标、模型名、状态、已运行时间和展开入口，长模型名省略但
  保留完整可访问名称与 title。首页最多三条，抽屉每页十条，数字与接口口径不变。
- 手机行支持点击及键盘展开/收起，详情显示令牌、首响应、协议和可选请求 ID；同一请求
  轮询更新时不丢失展开状态。仅改变 Classic 呈现，无后端、计费、Redis 契约变更。

## 接口契约

`GET /api/log/self/active` 使用 `UserAuth`，始终读取登录用户自己的请求；管理员也不
跨用户读取。查询参数为 `page`（默认 1）、`page_size`（默认 10，最大 50）、`search`
（模型、令牌名称、请求 ID）、`status`（`waiting_response`、`receiving`、`processing`、
`retrying`、`completed`）、`token_id`（可选正整数）。搜索最长 256 个字符；非法参数返回 400，
无登录身份返回 401，活动存储读写不可用返回 503。响应设置 `Cache-Control: no-store`。

响应沿用 `{success,message,data}`，`data` 包含：

- `items`：当前页请求（含未到期的结束记录）；`total`：筛选后的总数；`page`、`page_size`。
- `summary`：当前用户所有活动请求的 `total`、`streaming`、`non_streaming`、`waiting`、
  `active_tokens` 和 `by_token`（令牌 ID 字符串到请求数）。摘要不受列表过滤影响，且只统计
  尚未结束的活动请求；结束记录不计入正在使用的令牌或 `active_only` 筛选。
- `scope`：`cluster`（共享 Redis）或 `instance`（未配置 Redis，仅当前进程）。
- `observed_at`：服务器 Unix 毫秒时间，用于客户端校准运行时长。

请求字段：`id`（服务端生成的生命周期身份）、`request_id`、`token_id`、`token_name`、
`model_name`（客户端原始模型）、`request_type`（入站协议）、`is_stream`、`started_at`
（Unix 毫秒）、`first_response_ms`（未响应为 null）、`status`、`retry_count`，以及结束后
才提供的 `completed_at`（Unix 毫秒）。`completed` 表示生命周期已结束，包含失败、取消和
panic，不承诺业务成功。活动请求优先，同类内按 `started_at` 和 `id` 稳定排序。

`GET /api/token/search?active_only=true` 在原有 `keyword`、`token`、`status`、`p`、
`size` 条件上增加活动令牌交集；活动 ID 由当前用户的注册表快照产生，不接受客户端 ID
列表。交集先于数据库计数和分页，空集合返回零条，仍返回脱敏密钥。未传或传 `false`
保留原行为；无效布尔值返回 400，活动存储不可用返回 503。沿用原令牌搜索限流。
前端仅在活动令牌集合变化或错误恢复时刷新此列表，不每两秒重查令牌数据库。

令牌行的活动数按钮使用该行稳定 ID 打开 `token_id` 筛选抽屉，切换令牌清空搜索、状态
和分页。抽屉顶部摘要仍为当前用户全部连接，底部匹配总数对应当前筛选结果。

## 生命周期、多节点与安全边界

- 请求建立 RelayInfo 后注册，响应首个数据时更新状态；同一次客户端请求重试仍是一条，
  首响应时间在重试时清空。完成、失败、panic 由 defer 标记结束，客户端取消通过 context
  回调及时结束活动统计；两条收尾路径幂等。结束时间仅记录一次，迟到首响应或重试不复活
  请求；结束后保留 5 秒再清理。后台循环在无 Redis、无人查询时也清理到期内存记录。
- Classic 显示“已结束”，运行耗时冻结在 `completed_at`；结束但没有首响应时显示
  “未收到响应”。只剩结束记录时面板仍可见，活动计数为零；界面提示结束记录保留 5 秒。
- 首响应表示首个响应数据，不保证是第一个可见文字。非流式尚未获得响应时为处理中。
  `first_response_ms` 以客户端请求开始为基准；重试后的值包括此前等待。观察回调独立于
  原有计费首响应指标，不重置原指标。流式标记按入站请求记录，不随内部协议转换变化。
- 仅跟踪同步 Relay 及任务提交 HTTP 请求的生命周期；异步任务提交成功后的后台生成不属于
  当前连接，WebSocket 表示当前连接生命周期，不宣称逐轮请求数量。
  旧 Midjourney 代理、任务查询、管理接口和注册前的鉴权/校验失败不在此次跟踪范围。
- Redis 每 2 秒批量发布和续租，活动租约 15 秒，结束记录租约固定截至 `completed_at + 5 秒`，
  不因重新发布而续期；过期条目查询时原子清理，到期删除失败由
  待删除重试与 TTL 兜底。请求路径不等待 Redis，不改变计费、路由和错误处理。
  页面另以 2 秒轮询，因此状态变化可有约 4 秒延迟，页面移除会有轮询延迟。
  短请求的结束状态也会发布，但网络失败、页面隐藏等情况仍不保证每条请求都被浏览器观察到。
  Redis 键为 `active_requests:v1:{用户ID}:data` 与 `:leases`，无刷新 60 秒自动过期；
  查询时清理 15 秒租约已过期条目。各节点须使用同一 Redis 数据库并保持系统时钟同步。
- 无 Redis 时使用进程内状态；配置 Redis 后查询失败返回 503，前端保留错误/过期状态，
  不能把不可用显示成零连接。浏览器页不可见时暂停轮询，页面卸载取消请求。
- 不保存或返回完整密钥、请求头、提示词、IP、渠道、上游映射模型和内部错误。
  不新增数据库表或迁移。活动统计按稳定 `token_id` 去重，名称仅用于展示。
  登录会话请求可能没有令牌 ID，会计入请求数，但不计入活动令牌数。

## 性能与部署边界

- 每个应用进程只有一个发布循环，固定 2 秒节拍写全部本进程活动快照，不按每个输出
  chunk 写 Redis；写入截止时间 500 毫秒，查询截止时间 1 秒。摘要和搜索在服务端读入
  该用户全部活动记录后计算，再返回至多 50 条，并非 Redis 内部的游标分页。
- 无 Redis 时查询扫描本进程注册表；大量用户或极高并发场景需要独立压测，本次目标为
  数十条连接的可用性。多进程无 Redis 只代表响应请求的实例，前端明确提示范围。
- 这是短期状态观察，不能代替历史日志、准确在线人数或并发限额。节点退出后最多保留
  一个租约周期；网络分区中无法联系到的节点也会在租约后退出汇总。
- 全节点升级后才能完整汇总所有节点；回滚应用版本无需数据库回滚，遗留 Redis 键会
  自动过期。无新增环境变量、数据库表和依赖。Default 模板不在本次 UI 范围内。
