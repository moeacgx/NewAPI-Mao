# MCP 管理接入

## 余额与消费的展示契约

余额、累计消费、令牌额度、用量和商务额度查询会在对应对象中追加
`money_display`，例如 `{"quota":"$9200.66","used_quota":"$27780.87"}`。
Agent 向用户报告时应直接使用这些文本，不能再次换算，也不要把原始 quota
作为余额展示。顶层 `money_display_settings` 提供显示模式、符号、
`quota_per_unit`、美元到显示货币的倍率及汇率来源。

原始数值、编辑读取和写入参数继续使用既有单位与精度，普通 REST 响应不变。
订阅总额度为不限额哨兵值、或令牌 `unlimited_quota=true` 时显示 `Unlimited`；
实际消耗仍显示对应金额。只有明确工具中的额度字段参与换算，
发票/支付金额、渠道余额、模型价格和动态来源字典不二次转换。

USD/CNY/CUSTOM/TOKENS 跟随站点配置；CNY 与 `/api/status` 共用有效汇率缓存。
货币文本固定两位且不缩写，非零小额最低显示带原符号的 `0.01`；
这与当前 Classic 余额精度一致，Default 的小额多位与本地化排版仍由页面负责。
TOKENS 返回原始点数并明确标注，不能当作模型实际 token 用量。
展示发生在安全投影及业务回执持久化之后，旧成功回执重放也补充展示；
展示失败保留成功状态并追加说明，不能因此重复写操作。

## 目标与范围

为本地 Codex、Cursor 等客户端提供 HTTP MCP 管理入口，并在 Default 与 Classic 中提供接入说明、工具参考、调用密钥、调用记录四个页签。管理工具复用现有后台业务接口，覆盖渠道、用户、分组、模型、令牌、日志、统计、兑换码、订阅、工单及系统运行信息等能力。

## 实现契约

- MCP 端点为 `/mcp`，采用无状态 Streamable HTTP 的 JSON 响应模式；实现初始化、ping、工具发现和工具调用。
- 浏览器管理接口位于 `/api/mcp`，仅管理员可访问；调用密钥及记录按创建者隔离。
- `GET /api/mcp/tools` 返回工具数组，每项包含 `name`、`description`、`category`、`write`、`min_role`、`inputSchema`。
- `GET /api/mcp/keys?p=1&page_size=20` 返回 `{items,total}`。密钥元数据包含 `id,name,key_prefix,tools,created_at,expires_at,last_used_at,revoked_at`。
- `POST /api/mcp/keys` 接收 `{name,tools,expires_at}`；返回 `{key,secret}`，完整密钥只显示一次，不存入浏览器持久化存储。`DELETE /api/mcp/keys/:id` 撤销本人密钥。
- `GET /api/mcp/logs?p=1&page_size=20` 返回 `{items,total}`，记录包含 `id,key_id,tool_name,request_id,success,duration_ms,created_at`。
- 以上管理响应沿用 `{success,message,data}` 包装。时间采用 Unix 秒；过期时间必须在未来，且不超过 `253402300799`（9999-12-31 23:59:59 UTC）。
- 工具参数以显式注册的路径、查询和请求体契约为准，不接受任意 URL。写工具要求 `request_id`，服务端持久化去重，重复标识不得执行不同请求。

管理页面入口为 Default `/mcp-management`、Classic `/console/mcp`，均由管理员身份和 `admin.mcp` 导航开关控制。两套开发服务器均代理 `/mcp` 到 API 服务；Default 按路径边界匹配，避免把 `/mcp-management` 页面代理出去。

两套模板的接入页采用居中限宽卡片，桌面显示操作步骤与客户端配置两栏，
窄屏堆叠；Cursor/Codex 切换只展示对应配置。工具搜索按名称、说明和分类匹配，
分类显示本地化名称，筛选值仍使用服务端分类标识。工具清单在固定高度区域滚动。
密钥表格仅展示授权数量，通过“查看权限”弹窗搜索已保存的白名单，避免数百个
工具名撑高单行。历史工具或暂时无法读取目录时保留保存的名称，标注详情不可用，
不推断成只读权限。此展示调整不修改 API、工具授权和一次性密钥生命周期。

## 工具调用约定

工具目录的实现位于 `service/mcp_catalog.go`。各工具有固定 HTTP 方法、固定路由、输入 schema、角色门槛和必要的细粒度权限；同一目录用于 MCP 发现与管理页面。新增工具必须加入路由契约测试，明确输入与输出边界，不能自动把新增后台路由全部暴露。

目录在原 89 个工具基础上扩展为后台管理工具集。实际可见数量由当前用户角色、
细粒度权限和密钥授权共同决定；准确目录以 `GET /api/mcp/tools` 为准。
密钥保存明确工具名列表，新增工具不会自动获得已有密钥的授权。

2026-11-15 本轮目录快照为 368 个工具，覆盖 20 类功能：
160 个查询工具、208 个写入或主动操作工具。
需要管理整个后台时，使用具备相应权限的管理员创建密钥，按分类选择所需查询和写入工具。
Root 专属配置、插件源码、本人推理密钥及部署日志仍需 Root 身份和相应工具授权。
目录按当前可见结果批选，搜索或切换分类不会取消其他分类已经选中的工具。

工具参数采用以下结构，值的业务含义沿用对应后台接口：

```json
{
  "path": { "id": "42" },
  "query": { "p": "1", "page_size": "20" },
  "body": { "status": 2 },
  "request_id": "disable-channel-42-20261115"
}
```

上例是参数结构说明；各工具只接收自己的 schema 所允许的字段。例如停用渠道：

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "newapi_channel_status_set",
    "arguments": {
      "path": { "id": "42" },
      "body": { "status": 2 },
      "request_id": "disable-channel-42-20261115"
    }
  }
}
```

`path` 与 `query` 的值使用字符串；请求体保持原始 JSON 数字文本，避免浮点转换改变大整数。
本地数字 ID 限定正整数；插件版本、扩展 ID、供应商部署 ID 等只在目录显式声明时
允许安全的字符串标识，不能包含路径分隔符或目录穿越。分页每页上限 100。
写请求标识为 1–128 个英文字母、数字、下划线或短横线。
少量真实只读 POST（草稿解析、删除预览、本人密钥读取等）按其实际副作用分类，
不会因为 HTTP 方法是 POST 就保存正文或密钥回执。

渠道测试与余额刷新会访问上游，即使原路由使用 GET，MCP 仍标记为主动操作并要求请求标识。
原 `newapi_channel_update` 保留窄字段契约；完整配置由独立的
`newapi_channel_config_update` 和 `channel.sensitive_write` 控制。
单工单状态使用 `open/processing/resolved/closed`；批量接口按其 schema 支持归档状态。

### 添加模型与测试的实际范围

“添加模型”分为三步：`newapi_model_create` 创建展示元数据，
`newapi_channel_create` 或 `newapi_channel_update` 配置渠道的 `models`，
最后还需要符合站点现有价格配置才能推理。元数据创建不会自动绑定渠道或设置价格。
修改渠道模型时，先读取现有完整 `models`，合并后保存；该字段是逗号分隔的完整列表，
不是追加单个模型的补丁。当前没有单独的模型追加/移除工具或并发版本校验。
MCP 的完整渠道模型 CSV 上限为 8192 字节、512 项；超过上限或内容无法安全返回时
整体报错，不把截断或 `[redacted]` 列表交给客户端回写，需到后台处理。
写入时单个模型名最多 255 字节，拒绝空列表、空项、纯空白项及开头/末尾的多余逗号，
避免生成空名称的渠道能力；读取允许最长 512 字节的历史模型名用于诊断。

`newapi_channel_models` 返回宿主内置参考目录的分页结果
`data:{items,total,page,page_size}`，默认每页 20 条；使用字符串查询参数
`p/page_size` 翻页，每页最多 100。分页仅适用于进程内私有 MCP 调用，
普通后台 `GET /api/channel/models` 保持完整数组响应。参考目录不是实时上游发现。

模型创建至少提供 `model_name`；`status` 与 `sync_official` 省略时为 `0`，
需要启用时显式提供 `status=1`。`vendor_id=0` 表示不绑定供应商。
`endpoints` 使用 JSON 字符串，而非直接 JSON 对象。模型、供应商和标签的写工具
提供明确字段 schema；完整更新必须提交所有编辑字段，不能只提交新名称而清空其他配置。
GET 返回省略的空字符串、未绑定供应商 ID 等字段，需要按 schema 补齐后再保存。
只读的渠道绑定、匹配结果和分组名称不能原样塞入更新 body。

单渠道测试参数示例：

```json
{
  "path": { "id": "42" },
  "query": {
    "model": "local-model",
    "endpoint_type": "openai",
    "stream": "true"
  },
  "request_id": "test-channel-42-openai"
}
```

`endpoint_type` 可省略由宿主自动选择，或使用 `openai`、`openai-response`、
`openai-response-compact`、`anthropic`、`gemini`、`jina-rerank`、
`image-generation`、`embeddings`。这表示现有宿主测试入口的可选协议，
不保证每种渠道都支持这些模式；流式测试返回最终摘要，不返回生成内容或 SSE。
宿主明确不支持 Midjourney、Suno、Kling、即梦、豆包视频、Vidu、任务插件等
渠道的此类测试，需要各自的异步任务验证流程。MCP 不提供任意测试请求体。

新增的模型接入流程支持上游模型拉取、差异检测与应用、官方元数据同步、
Root 系统选项定价保存、完整渠道配置、批量测试及 Ollama 模型管理。
具体输入字段以各工具 schema 为准；检测、同步和安装可能访问上游或触发任务，
先保存返回的任务 ID，再查询状态。

### 配置、内容和文件管理

- `newapi_settings_list` 使用 `query.key` 精确读取或 `keyword/p/page_size` 分页。
  返回 `{items:[{key,value,redacted}],total,page,page_size}`；值保持字符串格式。
  凭据隐藏且 `redacted=true`，不能将 `[redacted]` 占位符保存回去。
- `newapi_setting_update` 仅允许已存在的选项名；值使用字符串，JSON 配置先序列化。
  合规声明字段不可经通用设置修改，保留宿主会话确认流程。
- 安全审计、请求归档、对话归档和模型守卫保存时，读取 `config_version`，
  写入 `expected_version`。字段缺失、版本冲突、凭据动作错误均由真实路由校验。
- 工单正文、提示词正文、通知编辑配置、归档正文和本人令牌密钥使用独立授权工具。
  旧摘要工具不会因为新版本扩展而自动获得秘密读取权限。
- 文件工具采用 `body:{filename,content_base64}`，只转换为目录固定的 multipart 字段。
  不接受服务器文件路径或任意下载地址。扩展市场安装的 SHA-256、预期身份、版本、
  目录地址和归档路径要全部提供或全部省略；实际校验仍由宿主执行。
- 任务插件安装、激活、版本删除、运行时开关沿用宿主生命周期。`dryrun` 路由仍为
  宿主未实现的 501，未注册成“可用测试”。异步媒体生成和压力、完整计费测试属于
  推理面验证，不等于管理入口的连通性测试。

### 协议与响应

- 支持 `2025-03-26`、`2025-06-18`、`2025-11-25` 协议版本，提供 `initialize`、`ping`、`tools/list`、`tools/call`。不创建服务器会话、不提供 SSE 订阅或旧式 SSE 端点。
- POST 使用 `Content-Type: application/json`，`Accept` 同时包含 `application/json, text/event-stream`。通知成功返回 202 空正文；非 POST 返回 405。后续请求中的不支持版本返回 400。
- JSON-RPC 方法错误返回标准错误结构；工具业务失败通过 `isError: true` 返回。HTTP 200 本身不代表工具成功，需检查工具结果。
- `newapi_context` 返回当前身份、角色、密钥 ID 与可调用工具，不复用会触发返佣结算的 `/api/user/self`。
- 响应先做字段投影，再返回客户端及保存写请求回执。错误不回传上游原文、SQL、请求正文或凭据。各模块使用明确的响应契约；独立内容读取工具仅对显式获授权的客户端提供正文。渠道取密钥等仍需宿主交互安全证明的接口不绕过门禁。
- 模型、供应商和分组标签的读改写工具使用专用元数据白名单，保留覆盖更新所需字段。遇到含凭据或超出边界的元数据时拒绝整份结果，不返回被截断或缺字段的可编辑对象。渠道保留 `group_details` 的显示名称；模型的 `enable_groups` 保留业务 code，并批量补充 `enable_group_names` 用于展示。

## 权限与安全边界

调用密钥独立于模型推理令牌与后台登录凭证，数据库只保存高熵密钥的摘要。工具发现只返回已授权且当前角色可用的工具。每次调用重新校验所属用户状态、当前权限、有效期和撤销状态，经过原后台路由鉴权和细粒度权限链。

工具采用显式白名单，不暴露登录挑战、支付回调、任意文件访问和任意路由代理。用户密码重置、凭据轮换、在线更新等有独立管理工具和角色门槛，沿用原业务校验。本人推理密钥读取是 Root 独立授权的只读工具，不保存响应。审计不记录参数、密钥或完整响应。

跨域来源校验、请求体和响应大小限制、分页边界及调用错误应在服务端实施。MCP 密钥不得成为可直接访问任意后台 API 的通用凭证。

每实例每密钥每分钟最多 60 次 MCP 请求，最多 4 个在途请求；此限制独立于管理员的后台限流豁免，不是跨实例全局配额。原有摘要工具参数最多 64 KiB、内部响应最多 32 KiB；完整管理工具参数最多 1 MiB、响应最多 4 MiB。文件工具外层 JSON 最多 8 MiB、解码文件最多 6 MiB。宿主自身更小的限制继续生效；超限时缩小查询范围，不静默截断可编辑数据。Origin 沿用站点可信来源判定。调用密钥不具备浏览器会话，不能代替 Passkey、安全证明或登录会话。

### 重试与记录生命周期

同一密钥下的 `request_id` 唯一。首次执行前持久化参数摘要与独立随机所有权标记，
冲突后回读判断所有权，不以 MySQL `RowsAffected` 推断是否首次执行。
新增完整管理写工具首次返回完整投影结果；持久化只保存资源 ID、版本、状态和计数等
metadata，重试返回 `result_not_retained=true` 和 `receipt`，不再次执行业务。
生成兑换码等瞬时秘密结果完全不进入回执。普通回执限制 48 KiB，过大时只留完成摘要。
原摘要写工具保留原脱敏回执契约；不同参数复用标识仍拒绝，跨密钥不共享去重域。

审查确认 `newapi_affiliate_records` 和 `newapi_benefit_report` 的宿主读取过程分别会
结算成熟返佣、处理过期券，因此这两个原工具现明确标记为写操作并要求 `request_id`。
旧客户端调用需补充标识；响应仍保持摘要范围，不因该修正开放正文或秘密。

进程异常、超限、业务执行后响应不明确或回执保存失败时保留 `pending`，不自动重试或清理。客户端应查询业务状态后人工处理，不能换标识直接重复写。不能将此机制理解为业务事务与回执存储间的原子提交。

调用审计记录创建者、密钥 ID、目录工具名、请求标识、结果、耗时和时间，不记录调用参数或完整业务响应；请求标识中不要放入敏感数据。未知工具统一记为 `unknown`。写回执另存脱敏结果或完成摘要用于去重；瞬时秘密结果不持久化。当前没有自动过期清理：撤销密钥、调用审计及去重记录均保留；部署前应按实际调用量安排数据库容量与维护策略，不能清理仍可能被客户端重试的请求标识。

## 数据与兼容性

新增独立密钥、调用审计及写请求去重所需数据；使用 GORM 的跨数据库模型，兼容 SQLite、MySQL 和 PostgreSQL。迁移随应用既有迁移流程执行，不在开发期间修改生产数据库。原后台、推理、计费和分组标识契约保持兼容；分组展示沿用显示名称。

## 接入

Codex 配置示例（地址替换为当前服务地址）：

```toml
[mcp_servers.newapi_mao]
url = "http://127.0.0.1:3000/mcp"
bearer_token_env_var = "NEWAPI_MCP_KEY"
```

完整密钥放入客户端本地环境变量 `NEWAPI_MCP_KEY`。远程使用可访问的 HTTPS 地址。客户端连接后先调用 `newapi_context` 核对身份及授权范围。

创建密钥时应同时勾选 `newapi_context`；它与其他工具一样按密钥授权。密钥名称最多 100 个 Unicode 字符，过期时间为未来 Unix 秒。配置复制只包含环境变量名，密钥回执关闭或离开页签后不能重新查看；遗失时撤销旧密钥再创建。
