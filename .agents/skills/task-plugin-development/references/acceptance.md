# 任务插件验收矩阵

选取当前需求、计费模式和协议实际支持的行。每行记录用例/断言、目标宿主与插件版本、
结果或不适用理由；没有跑到的阶段不能写已通过。不要为无关能力扩大开发范围。

## 最小交付证据表

| 层         | 必须证明的行为                                             | 典型遗漏                                               |
| ---------- | ---------------------------------------------------------- | ------------------------------------------------------ |
| 市场和安装 | key/version/原始字节 hash 与编译 meta 一致；安装后明确激活 | 同版本覆盖、混错源、API v1 新字段旧宿主拒绝            |
| 路由和身份 | 实际客户端路径、规范名/别名；只按别名设置权限价格仍成功    | decode 先拒绝别名，后面的渠道 mapping 根本没机会执行   |
| 上游请求   | method、私有路径、认证、模型、必要参数及显式零值正确       | 客户端路径被上游私有前缀污染，客户端字段覆盖凭据       |
| 响应       | 真实脱敏包裹、HTTP 错误、业务失败、缺字段、未知状态        | 固定假响应碰巧通过，现场 Completed 包裹失败            |
| 预扣和结算 | 钱包/令牌余额及 used_quota、最终日志 quota 与预期一致      | 按次乘上所有用量、实际计费没覆盖估算、重复扣/退        |
| 用量和统计 | 响应→hook→宿主→日志列→统计，实际数值逐段一致               | 有 usage 却日志 0；输出免费被省略；错误把积分当 Token  |
| 生命周期   | 同步终态不轮询，异步可取回、历史版本和状态正确             | retainResult 清除后承诺查回；poller 用错版本或丢 state |
| 失败隔离   | 无错误副作用；退款一次；原始密钥/错误正文不外泄            | parse/DB/结算错误被成功状态掩盖；不确定受理后重试      |

## 按类型补齐断言

### 性能失败过滤

- `requiredCapabilities:["task-performance-filter@1"]` 与函数导出双向校验；旧插件不声明能力保持兼容。
- 精确测试 false/true/null/undefined、错误返回类型、异常、执行与排队超时；只有 false 排除。
- 真实路由验证 HTTP/解析/业务失败、日志保留、退款及成功 Token；钩子不能覆盖宿主策略和管理员过滤。
- 核对输入白名单、无query/正文/凭据，处理中版本切换保持旧对象，执行中客户端取消仍不采样。
- 分发前错误日志不等于性能样本：错路径保留日志、处理器不执行、性能摘要不变，禁止通过删除日志美化统计。

### 有 Token 的同步插件

- 正常用量如输入 486、输出 70：API 返回、完成 hook、消费日志两列与渠道统计逐项相等。
- 对声明支持两种模式的插件，分别配置固定按次和输入用量表达式。按次金额固定；输出单价为 0 时仍记录 70 个输出。
  验证零输入、零输出、两者皆零，区别于缺失 usage。
- 输入/输出缺失、负数、小数、字符串、非有限值、超过字段范围，依据真实合同拒绝或标未知。
  “标未知”必须有宿主支持的字段存在性合同；默认 0 的日志列不能代替未知状态。
  不把失败钩子保留预扣的行为误报为“实际零用量免费”。
- 检查适配器在验证中是否先做 int32 饱和，再传给统计；分别复现单字段超界和求和超界。
  用已接受的真实原始数量统计，不将截断后的额度数充当 Token。
- `retainResult:false` 在响应交付前仍可读到用量，落库后不保留用户内容或渠道凭据；
  结果清除不应导致用量统计漏记，亦不能从历史空结果重造用量。
- 成功调用后分别查询消费日志、渠道指标和模型广场性能明细；三者不是同一存储链路。同步性能成功样本
  只在真实请求已发送且 immediate 成功时写入，失败样本要验证策略码/失败过滤、取消、本地错误与 pending
  隔离。非流式样本的 TTFT 应为 0，TPS 与整体延迟口径保持一致。

### 异步视频、音乐、图片与源任务

- 选择声明的 `per_task` 或 `batch` 主路径；对 batch 使用不同 ID、不同状态/数量并打乱顺序。
- 覆盖非终态→成功、失败、无法识别；不是所有未知状态都能归类进行中。
- 当供应商返回实际秒数、clips、图片数量或 credit，比较预扣估算与完成事实的单位，
  不默认它们等于文本 Token。未提供完成用量时明确其合同，不凭输出文本补算视频 Token。
- 带源任务的接口验证不同用户/分组/模型/渠道/版本拒绝，未授权时不能发供应商请求。
- 重复轮询、激活新版本、关闭新提交和历史版本读取，用本地持久化 pin 合同断言退款与结果。
- 有媒体下载时按协议验证列表、认证、URL/重定向、大小和类型、过期与取消。
  本地未支持远程媒体或协议外观时不能声称兼容。

### 零价格保存问题

先定位 Default 或 Classic 页面，并核对请求 payload、选项持久值、刷新后的表单值和后端计算。
输出价格 0 不等于未设置；显式 0 不能被 `||` 或空值默认替换成输入价格。
按量编辑器和任务 `u()` 表达式是不同配置路径，分别复现，不用切换收费模式掩盖故障。

## 三层验证，逐层增加证据

1. **协议回放**：从文档和脱敏现场结果构造确定性 fixture，严格断言返回结构与错误，不只检查不抛异常。
   Node 可作快速检查，但目标宿主实际 JS 引擎与编译器是兼容性门禁。
2. **宿主集成**：模拟供应商，用真实 Gin 路由、认证、渠道和测试数据库，断言调用次数、
   权限/别名、钱包/令牌余额、任务状态、消费日志与统计。供应商成功而 DB/结算失败也要覆盖。
   按当前授权选择钱包或订阅；未验收的资金类型明确列出，不能借同一函数就宣称都通过。
3. **版本和上线**：最低承诺宿主与当前宿主各跑相应合同。老宿主调用兼容并不证明它支持新统计。
   只有得到授权再安装/部署或收费验证；先复用已有脱敏现场响应，避免无必要重复付费调用。

## 已存在的验证入口

从目标宿主根目录执行，按修改包范围缩小，不把宽泛命令当作唯一验收：

```powershell
go test -mod=readonly -timeout=60s ./pkg/jsplugin ./relay/channel/task/jsplugin -count=1
go test -mod=readonly -timeout=60s ./controller ./service ./router ./relay -run 'TaskPlugin|Jev|Task.*Usage' -count=1
```

先确认目标宿主 CLI 入口存在且二进制来源正确，可运行：

```text
new-api plugin lint <plugin.js>
new-api plugin test <plugin.js> --fixture <fixture.json>
```

无可用二进制时，复用 `pkg/jsplugin.ReplayFixture` 和现有 Go 测试，或经审阅的 overlay harness；
不要为编译 CLI 伪造缺失的前端嵌入产物。`Fixture` 每例包含 name/hook/args 与 expected 或 expectedError，
成员 hook 使用 member，嵌套协议 hook 使用 path；格式以 `pkg/jsplugin/fixture.go` 为准。

Cloudflare 专属回归只在本地插件仓库存在对应脚本时执行，不泛化为所有插件必需：

```powershell
node --test --test-timeout=60000 tests/cloudflare-jev.test.mjs
node scripts/validate-index.mjs
node scripts/verify-cloudflare-host.mjs <最低兼容宿主目录>
$env:CLOUDFLARE_JEV_EXPECT_TOKEN_LOGS = '1'
node scripts/verify-cloudflare-host.mjs <已含统计修复的宿主目录>
Remove-Item Env:CLOUDFLARE_JEV_EXPECT_TOKEN_LOGS
```

环境变量只作用本次命令会话；旧测试版本可能不识别它，先读脚本和断言再执行。
结果报告列实际用例数和退出状态，不能仅以数量宣称所有链路已覆盖。
