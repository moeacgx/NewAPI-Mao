# 任务插件开发与验收

目标是一次交付完整可验证的插件合同：安装、选渠、调用、交付结果、结算、日志与统计。
不能把“HTTP 200”“Node 测试通过”或“模型可以调用”当作完成标准。
技能只约束当前任务，不授权合并、收费推理、生产安装或部署。

## 开始前确认四个边界

1. **改哪层**：先查官方是否已有同协议实现。优先复用官方插件；缺宿主能力时先比较官方宿主补丁，
   已有能力未同步则移植必要变更。只有独立协议或验证过的剩余缺口才定向开发。
   TypeSafe 直连和 Cloudflare 转接属于不同协议，不能仅凭模型相同就互相替代或重复上架。
2. **在哪个仓库**：主仓库负责鉴权、分组、选渠、资金、持久化与日志；
   `maolaonewapi-plugins` 负责可独立版本化的供应商适配。先读各自规则，不把子仓库测试或发布规则混用。
   工作区与分支隔离遵守根目录约定，不切换或覆盖其他任务工作区。
3. **对照哪个版本**：记录宿主提交、官方插件仓库提交、插件版本及源码 SHA-256、目标部署版本。
   `apiVersion: 1` 不足以证明宿主支持所有新增字段；以实际编译器、路由和结算实现为准。
4. **支持什么行为**：确认客户端路径、模型名、上游身份、同步/异步、计费模式、结果读取需求。
   不把“SDK 同步等待”误认成供应商 HTTP 同步响应，不把上游路径强加给客户端。

先读根目录 `AGENTS.md`、`docs/developer/README.md`、`docs/developer/official-task-plugins.md`。
涉及表达式必须读 `pkg/billingexpr/expr.md`；涉及独立仓库先读 `docs/developer/extension-repositories.md`。
按任务阅读 [官方模式与本地边界](references/official-patterns.md)，选择生命周期相近的实现参考，
不要复制全部供应商特例。编码前在 `docs/workflows/` 写明合同、范围和验证计划。

## 沿着真实调用链检查

```text
市场源码/哈希 → 宿主编译 → 安装/激活/节点运行时
客户端 decode → 模型权限/分组/选渠 → 上游模型映射 → 预扣
buildSubmitRequest → HTTP/业务状态 → parseSubmitResponse
同步 immediate 或轮询终态 → 完成用量 → 持久化/结算 → renderer
消费日志 → 统计导出/渠道指标 → 用户界面
```

- 每个断点区分“输入存在”“实现消费”“持久化或返回可见”，不要只搜到字段就认为接线完成。
- 节点版本、活动插件、路由快照与渠道绑定分别确认；安装不等于激活，激活不等于所有节点刷新。
- 偶发错误按请求 ID 关联处理节点、活动源码 hash、decoder 阶段和选中渠道，
  先区分跨节点版本差异与单请求逻辑错误；不要只看一次成功或一个节点的配置。
- 本仓库当前 Task Plugin=62，AtlasCloud=61；迁移时核对 `constant/channel.go`，不能套用官方编号。
- 编译器支持 `protocols`、query、dynamic、SSE 或 `upstreams` 字段，不代表本地入口已可用。
  不支持的能力要列为阻断或范围外；不降级为表面成功。
- `plugin source failed validation` 是可能经过脱敏的概括错误。取待安装文件的原始字节和 hash，
  用目标宿主编译器离线重放，区分源码/编码、meta、hook、版本冲突和哈希错误。
  不因看到 query/dynamic 或 profile 声明就猜它导致安装失败，也不删除声明来绕过校验。

## 实现中必须保持的合同

### 模型、路径与权限

- 客户端模型用于令牌权限、选渠、价格和显示；`ctx.upstreamModel || ctx.model` 用于供应商请求及能力表。
  别名必须通过 decoder 和声明模型检查，不能在渠道映射发生前拒绝，也不能提前替换客户端身份。
- 显式验证规范名、别名、无映射/错映射、大小写碰撞。新别名应使用仅含该别名的价格和权限配置验收，
  避免测试环境的规范名兜底掩盖缺口。
- 原生路由与兼容协议外观各自解码，复用同一规范化请求与参数校验。
  客户端统一路径是公开合同；Cloudflare 等上游私有路径留在适配器中。
- 地址和凭据来自宿主渠道，客户端不能覆盖；资源下载也必须检查凭据作用域和宿主 URL 防护。
  源任务引用先经宿主授权，再使用其上游 ID。

### 响应与生命周期

- 以脱敏真实响应为基准，测试 HTTP 状态、业务失败以及供应商合法包裹层。
  只展开协议声明的层级，不递归寻找“看似成功”的结果；不能把 HTTP 200 当作业务完成。
- 同步真实终态才给 `immediate`；没有供应商任务 ID 时使用宿主公开 ID，不虚构轮询能力。
- 查询上下文不保证有提交 `requestBody`；跨轮次状态使用 `state`，当前结果使用 `taskData`。
- 未知状态返回 `UNKNOWN`。批量结果逐任务核对 ID、模型、状态和用量；不能按数组顺序猜关联。
- `retainResult:false` 只影响持久化：结算和统计必须捕获实际用量，呈现器仍能取得完整内存结果；
  按本地事务边界核对落库、结算和 HTTP 返回次序，检查查询语义和“不再轮询”。
  历史结果已清除时不要承诺回填旧日志。
- 明确失败由宿主退款，重复轮询不能重复退款。上游是否受理不确定时不得盲目重试提交。
  任务落库后结算失败、客户端取消和原始错误脱敏要按本地资金边界验证。

### 用量、收费和统计分别验收

- 建一份字段表：**来源、单位、估算/实际、价格用途、日志目标**。Token、秒、张、片段、资源包积分不得互换。
  Kling 的资源单位和旧 `upstreamUnits` 不能自动当成 Token。
- `usagePurpose=facts` 返回估算事实；`billing_ratios` 返回旧按次规则确需的倍率，纯固定按次可返回 `null`。
  不统一规定所有插件都返回 `null`，也不把全部数字事实连乘。
  同时追踪宿主是否消费这些倍率；本地 .335 按次插件只校验钩子结果而不将其用于连乘，
  不能从官方钩子返回值推断本地最终收费。
- 完成钩子提供实际事实，不能省略免费输出的真实 Token。没有上游依据的字段保持缺失，不伪造为 0。
  若日志数字列默认 0，检查元数据是否能表达字段存在性；不要把默认 0 宣称为已观测的零用量。
  显式 `0`、`false`、空值与缺失分别处理，禁止 `value || default` 吃掉零值。
- `usageSchema`、模型 profile 和示例需与钩子一致。示例展示不参与结算，不能硬编码站点售价。
- 本仓库任务 `u()` 公式结果按美元换额度，聊天 `p/c` 公式按每百万 Token 单价；阅读当前计费文档，
  不靠修改管理员价格掩盖单位转换错误。预扣和结算必须使用同一冻结合同。
- 数字检查必须覆盖原始值、转换/饱和后的值以及输入输出求和。不能把饱和值作为真实统计，
  也不能为补统计改变费用。遵守本地公共安全转换，不引入不受限的浮点转整数。
  计费沿用既定饱和安全规则；统计在饱和前检查原始数量，异常统计不得反向修改费用。
- 响应中的 `usage`、完成 facts、数据库 `prompt_tokens/completion_tokens` 和渠道指标是不同出口。
  需要 Token 统计的插件必须核对整个链路，包含按次收费和输出价格为 0 的配置。

## 验证与交付门禁

使用 [验收矩阵](references/acceptance.md) 选择本任务适用行；不适用要说明原因。
测试只跑 Node 不够：用目标宿主 JS 引擎回放，再从真实路由经过认证、选渠、预扣、结算直到数据库断言。
零价格保存还涉及 Default/Classic 表单和选项存储；后端 Token 修复不等于价格编辑器已修复。

收尾明确区分：本地测试、CI、合并、插件安装激活、宿主发版、各节点运行时、线上验收。
依赖新宿主的插件必须说明兼容边界。只做已授权发布操作，保留旧版本源码、hash 和回退路径。
新增版本按目标发布仓库规则维护索引与版本说明；不要覆盖已发布版本或把同一插件换源重复显示。
有未验证项就列明，不把它们转成“已完成”。
